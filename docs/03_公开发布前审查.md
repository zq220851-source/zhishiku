# 公开 GitHub 前的必要人工审查

**当前候选包默认只建议推送 PRIVATE 仓库，不视作可立即公开的开源产品。**

- [ ] 确定软件许可（如 MIT/Apache-2.0/商业许可证）、商标和第三方依赖归属；未经授权不要给医学资料、图片、音乐、3D 素材添加开源授权。
- [ ] 查看 `business_module1_reference/` 课程/医药数据、`business_module2_reference/` 真实医学业务数据、`business_module3_reference/` 学术日报内容：是否自有/获授权？实际知识库、课件、客户/医生信息、语音录音不能放在公共仓库。
- [ ] 所有真实 `.env`、Key、Token、IAM/飞书密钥、服务器地址、运维日志、员工/医生信息均从提交和**历史 Git 记录**移除（只从最新文件删除并不足够）。有泄露必须轮换密钥。
- [ ] 依赖及许可证审查，第三方前端 bundle 与 3D 美术作品需确认再发布。
- [ ] 跨企业时：每企业独立账号、数据库、域名、模型凭证；医疗行业审核、隐私政策和员工告知义务需评估。
- [ ] 模块二的真实企业权限、模块三的 Worker 上线和语音对练兼容未完成，必须醒目说明。
- [ ] 在自有阿里云上海公网对外提供网页/接口时依实际业务办理 ICP 等备案，GitHub 仓库**不替代**备案。
- [ ] 用 `python scripts/prepublish_check.py` 扫描；**脚本只能辅助检查，不能代替人工审批。**

未有明确软件许可和内容授权之前，不要把仓库设成 Public。
