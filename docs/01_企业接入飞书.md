# 企业从 GitHub 下载后如何关联自己的飞书

**这不是把代码直接粘贴到飞书妙搭。** 推荐方式是：企业自建飞书网页应用（H5）作为入口，H5 站点和后端由该企业自行托管。自建应用只属于创建它的企业，不会自动跨企业共享。

## 各企业须单独完成的事项

1. 获取经授权的源码。在私有仓库中授予企业访问权限，或在核实许可后发布公共版本。企业独立部署，不能复用演示企业的数据库、飞书密钥、模型账号。
2. 准备企业自己的合规 HTTPS 域名及运行环境（初期 2C2G 仅基础服务低并发试验，**完整语音/AI 需要实际压测**）。配置独立 PostgreSQL、定期备份、HTTPS，按适用法律办理备案与安全合规。
3. 基于 `backend/.env.example` 建立服务端 `.env`：`DATABASE_URL`、`POSTGRES_*`、`PLATFORM_TENANT_ID`、`APP_PUBLIC_ORIGIN`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`，以及内部模块凭证。**不要提交 `.env` 到 GitHub。**
4. 从 https://open.feishu.cn/ 以本企业身份创建 **企业自建应用**，开启 **网页应用**，移动端主页指向企业自己的 HTTPS URL，按平台要求设置可信域名、相关权限、可用范围、重定向设置，并走企业审核发布。
5. 前端设置 `VITE_FEISHU_APP_ID`（仅 App ID 可公开）并构建 `mobile_app/dist`。使用 `backend/compose.feishu-h5.yaml` + `backend/deploy/Caddyfile.feishu-h5` 示例部署前，应人工核对目标域名、端口与实际镜像；不要直接开放旧模块一端口，也不要绕过备案。
6. 飞书 H5 通过 `tt.requestAccess` 获取临时代码，发给本公司后端 `/v1/mobile/auth/feishu` 校验。**每个员工需要事先被管理员开通，并正确绑定该企业的 Feishu `open_id`**，否则拒绝登录。
7. 用 Android/iPhone 飞书客户端分别测试课程表达 `learn`、访前冻结及实战 `visit`，尤其要检查麦克风、语音 SDK 权限、真实 AI 调用与退出登录。

## 必须隔离的东西

| 项目 | 每企业独立 |
|---|---|
| 飞书企业自建 App ID / Secret | 是 |
| 业务域名 + 服务端 | 是 |
| PostgreSQL、训练记录、员工身份 | 是 |
| 大模型网关 / 百炼语音 / LiveKit 凭证 | 是，或授权结算下的隔离凭证 |

**GitHub 负责代码版本分发，不负责托管数据库、运行 Python/Next.js、代办备案或替企业创建飞书应用。**
