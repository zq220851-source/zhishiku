# 两个场景的验收材料

目标是验证完整操作及数据回流，不只检查页面能打开。资料与说法均为虚构，不可作为真实医学结论。自然回答原文及预期在 `tests/fixtures/journeys.json`。预期先由测试作者写出，未用被测模型自动生成预期。

## 场景一 学完后发现错误再补学重练

学习材料：演示研究C-17只观察A类人群，记录X，无同期比较组，未测Y。

1. 在“学习与巩固”选择“把研究结论讲到证据允许的范围”，阅读三段讲解及资料边界。
2. 点“用医生的问题练一下”，面对医生对人群和指标范围的追问。
3. 输入：`嗯，我觉得B类也能参考吧，X好一点，那Y大概也会好，应该比别的更合适。`
4. 预期：原话完整保存，指出外推或比较依据的遗漏；不得给正式医学分、总分或直接宣称掌握。若模型提出追问，再答：`资料我没细看，反正差不多，您就放心吧。`
5. 打开相关讲解，随后“换种问法再练”。不要求额外做一遍选择题或闭卷题。
6. 输入：`换个人群我得先查入组范围。现在只有A类和X，没有比较组，也没测Y，所以不能推到B类或说更优。缺的我查原始材料，明天下午再回您。`
7. 预期：范围、比较局限能被识别；来源及原话可定位；本轮看过提示须标记；第一轮错误记录保留，不被第二轮覆盖。一次成功不标永久掌握。
8. 关闭页面再进入“最近练习”，应能恢复记录。停止并重启服务后同样可读回。

补充语义判例：`不能说所有人都适用，也不能说肯定比别的好。这里只研究A类的X，没有比较组，也没有Y；B类的证据我去查原始资料，明天下午回您。` 预期不能把被否定的错误话术按肯定主张判断。

## 场景二 一次拜访只练拿不准的地方

背景：虚构周医生，5分钟；上次关切人群范围；本次讨论C-17；科室用药未知。

1. 到“访前准备”，整理本次准备重点。
2. 预期：可以仅阅读准备单后结束，不要求开启模拟；每个推荐有背景ID；用药未知保持未知，不补造医生偏好。
3. 只选择“回应研究适用范围”，不必依次练开场、专业回应和收尾。
4. 输入：`这次我先确认您想核对哪类人群。C-17只有A类的X，没有同期比较组，B类和Y都没有依据，所以不能说更好。没核实的我查原始资料，明天下午跟您确认，今天不把还没查的说成已经做完。`
5. 预期：按本次试练范围反馈；“回到这份准备单”后，在原单中看到试练结果和行动提醒；准备单ID不变，没有新造四份报告。
6. 刷新页面后内容仍在。另一浏览器不能读取这个准备单。

自填背景：选择“填写我的拜访背景”，医生`A医院周医生（虚构）`；目标`讨论研究人群适用边界，确认是否需要补资料`；背景`上次医生问到人群范围；来源：虚构测试记录。科室用药情况未知。`

预期：试练引用自填背景、只评沟通行为，不自动引入C-17，不把用户报告认定为真实医生事实。

## 必须通过的失败情况

- API超时或非法JSON：显示失败，原话保留；同一请求重试不能重复追加。
- 模型伪造引用：不得判“已体现”；错误来源ID直接拒绝。
- 同时重复提交：一次回答只请求一次模型。
- 转写需要修订：保存原话修订历史，撤回旧反馈与当次证据，允许重新生成。
- 不同浏览器访问他人ID：404；无Origin写请求：403。
- 用户输入HTML：作为文字显示，不生成脚本或标签。
- 模型重写题目时泄露答案：回归检查禁止该问题，改用预设变式。

## 验证分层

1. 领域与HTTP自动化：测试替身只验证状态、持久化和安全边界，不能证明语义评价准确。
2. Playwright浏览器：真正点击页面走两条流程、刷新、失败重试、修订、历史和窄屏布局，模型是明确的测试替身。
3. 真实模型：同一虚构材料与口语回答，检查错误识别、正确回答、否定语境、访前推荐与准备单更新。一次真实调用通过只代表这些测试样本。
4. 真实语音服务：合成医生问题并转写回文字，确认链路可用；真人麦克风、噪声及延迟体验另行验收。
