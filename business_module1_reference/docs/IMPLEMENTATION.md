# 第一模块实施记录

用户已确认的流程：平时“学完就练，哪里不会补哪里”；访前“了解资料、找到本次准备重点，拿不准的再试练”。不增加强制课前测验、闭卷题、能力标签确认等关卡。第二模块在其他工作中并行，本次不修改。

## 开源结构取舍

1. OpenMAIC：核查 `lib/types/stage.ts`、`app/api/quiz-grade/route.ts`，提交见 `upstream.json`。源码已按该提交重新读取核对。借鉴可辨别的场景内容与独立简答评价请求，形成学习内容、练习状态、评价服务的分离。代码独立实现，未复制其源码。MIT项目的捆绑组件仍各有许可证，本次未引入这些组件。
2. 原评分接口在模型输出解析失败时给通用半分。本项目明确不采用：Pydantic校验结构、检查来源ID、逐字验证引用，失败时保存回答并重试；没有伪造成绩。
3. LiveKit Tasks/Workflows：参考短任务完成后返回结果的组织方式，本轮不引入其媒体服务，继续复用原包ASR/TTS。引入整套服务会增加部署及供应商适配成本，当前不足以证明必要性。
4. Haystack：参考先按元数据筛选的方式，但已有71份结构化课程、明确ID与只读SQLite查询，本轮直接结构化读取，不增加向量数据库和检索框架依赖。
5. Pydantic：实际依赖，用来验证模型返回的观察项、状态、原话位置、来源及字段类型。Schema验证只能保证结构，不能代替培训师对评价的校准。

## 与现有资料的关联

`knowledge.py` 直接读取原包课程JSON、course-skill-bridge和临床SQLite，资料状态保持原样。课文及来源可在页面查阅；评分只能评价明确提供的观察要求。临床训练范围并非获批说明书。书籍全文不在交接包里，不虚构全文检索能力。

`workflow.py` 控制状态、观察项及来源快照；`app.py` 控制HTTP输入和浏览器身份；`web/`负责展示，不承担评分和状态迁移规则。

学习：读取课程 → 创建本次练习 → 提交回答 → 按需一次追问 → 当次反馈；随时查看对应讲解，结束后允许重练。
访前：选择演示背景或自填 → 模型从候选交流环节中选重点并引用背景ID → 用户决定是否试练 → 结果更新原准备单。

模型未配置时使用明确标注的规则整理，不宣称AI预测；已经配置的模型发生错误时不静默退回脚本结果。

## 测试发现的修正

- 问法生成可能把参考答案写成医生问题。新增失败回归后改为从课程题目及人工编写的变式中取题；模型负责针对实际回答追问，不负责生成带答案的重练开场。
- 缺少可定位原话时，观察项转待核实，连同总体文字反馈一并降级，避免图上待复核而文字仍说“全部正确”。
- 修改转写撤销对应当次证据及准备单中的旧反馈，再允许重算；保留修订前后文本。
- 同一请求编号重复提交不会再次生成或重复记分；失败后同一请求可以恢复，网络异常不被当作知识错误。

## 部署与数据

仅监听127.0.0.1；写请求校验Host及Origin；Cookie为HttpOnly/SameSite=Strict；数据库按浏览器随机身份隔离。用户输入全部按文本渲染，防脚本插入。图片、患者或医生真实个人信息不在测试材料中。

原资料在 `reference/coach/`，不执行其中脚本，不修改旧状态和审核记录。新数据只在独立runtime目录。服务密钥在当前本机进程共享，仅适合单人原型，企业认证与凭证隔离不在本轮。

后续真实验证还发现：模型理解了否定语境，但把不相邻原话拼成了新引用；没有表现证据时还可能输出负数索引。已改为向模型提供可选择的原话编号，由程序回填原文与位置，禁止模型自由拼接引用。保留旧协议的严格逐字校验仅为历史兼容。此修正后真实模型4个语义验收场景全部通过，详情见验证记录。

个人记录按实际观察项保存沟通信号；原课程的回应和明确未知表现可影响自填拜访中的相关建议。原有医学能力标签仍保留作资料映射，不把行为反馈扩张成医学知识掌握结论。
