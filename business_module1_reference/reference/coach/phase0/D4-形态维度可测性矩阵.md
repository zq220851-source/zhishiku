# D4 · 形态 × 维度 可测性矩阵

> **状态**：已冻结（Phase 0 决策包）
> **用途**：决定 GATE-04 何时触发、哪些维度进入分母、权重如何重分配
> **依据**：V1.3 §1.5 双维能力评估；语料中语音/电话场景证据的稀缺性

---

## 0. 核心结论

**可测性由「观测证据是否存在」决定，不由「交互形态」简单二选一决定。**

这带来一个反直觉但重要的设计：**同一形态下，不同维度的可测性不同**。
电话不是"话术全不可评"——表达清晰度仍可从录音判，缺的是打断应答与非语言反馈。

---

## 1. 矩阵

> **字段来源**：形态取自 D1 画像卡的 `visit_context.channel`，取值 `面访` / `视频` / `电话` / `文字`（IM）。
> 形态字段的合法取值与画像卡 schema 完全一致——**两处不允许各自定义一套形态枚举**。

| 维度 | 面访 | 视频 | 电话 | 文字（IM）| 依据 |
|---|:---:|:---:|:---:|:---:|---|
| **COM-01 问题理解** | ✅ | ✅ | ✅ | ⚠️ | 问对了没有，听得出来 |
| **COM-02 回答结构** | ✅ | ✅ | ✅ | ✅ | 结构在文本里最清楚 |
| **COM-03 表达清晰** | ✅ | ✅ | ✅ | ⚠️ | 文字缺语调 |
| **COM-04 临场应变** | ✅ | ⚠️ | ❌ | ❌ | 需打断/意外情境 |
| **COM-05 情境适应** | ✅ | ✅ | ❌ | ❌ | 需非语言反馈 |
| **MED-01 知识准确性** | ✅ | ✅ | ✅ | ✅ | 文本即可判 |
| **MED-02 证据运用** | ✅ | ✅ | ✅ | ✅ | 文本即可判 |
| **MED-03 适用边界** | ✅ | ✅ | ✅ | ✅ | 文本即可判 |
| **MED-04 专业与合规** | ✅ | ✅ | ✅ | ✅ | 文本即可判 |

**图例**：✅ 可评 / ⚠️ 有条件可评（证据降级，评分需说明） / ❌ 不可评（移出分母）

---

## 2. 逐条说明

### COM-01 问题理解
所有形态可评。听医生问什么、药代答的是不是同一个问题，判断不依赖视觉或语调。

### COM-02 回答结构
所有形态可评。结构（有没有给结论、是否分层、是否收尾）是文本层面的。**IM 形态反而最清楚。**

### COM-03 表达清晰
- 面访/视频/电话：✅ 完整可评（有录音）
- IM：⚠️ 仅评结构与用词准确度，**不评简洁度与流畅度**（无语音）

### COM-04 临场应变
- 面访：✅ 可评（医生当场打断、临时提问）
- 视频：⚠️ 可评但证据降级（医生可能更少打断）
- 电话：❌ **不可评**。语料中电话场景缺少打断/意外情境的可观测记录
- IM：❌ 不可评

### COM-05 情境适应
- 面访/视频：✅ 可评（读得懂表情与反应）
- 电话：❌ **不可评**。无面部/语调线索时，"是否适配该医生"无法从音频可靠判断
- IM：❌ 不可评

## 2.5 与 D1 的字段契约

| D1 字段 | 取值 | 本文件的使用 |
|---|---|---|
| `visit_context.channel` | `面访` / `视频` / `电话` / `文字` | 决定本矩阵哪一行生效 |

**契约规则**：

1. `channel` 的枚举值**只能取 D1 schema 定义的四值**，本文件不得新增形态。
2. 新增形态（如「学术会现场」「科室会」）必须**先改 D1 schema**，再在本文件补行。
3. **未在 D1 枚举内的形态值，引擎按 `面访` 处理并在报告中标注「形态未识别」**——
   静默按面访处理会造成维度误评（面访的可评维度最多，会虚高得分）。

> **为什么这条要写死**：形态与维度的映射是判定"这个维度该不该计分"的依据。
> 枚举不一致意味着同一份训练记录在不同模块可能得到不同的可评维度集合。

## 3. 语料证据的诚实说明

**这是本文件最需要被看清的部分。**

我检索了全部 83 份课件文本中与语音/电话/打断/沉默相关的表达：

| 检索词 | 命中的**可测性证据** | 说明 |
|---|---|---|
| 电话 / 约见 | 无用于"可测性判定"的条目 | 语料提到电话拜访场景，但未定义可观测维度 |
| 打断 / 语速 / 停顿 / 沉默 | 有场景描述，无「哪些维度在电话里可判」的规则 | 语料不支持形态维度的判定 |
| 录音 / 视频 / 远程 / 线上 / 直播 | 无维度可测性判定 | — |

> **结论**：**本矩阵的形态→维度映射，是本产品的设计决策，不是语料结论。**
>
> 【本产品设计决策】依据 V1.3 §1.5「不同交互形态下各维度可评价性不同」的框架要求，
> 结合端到端原型中电话形态已验证的权重重分配逻辑，制定本矩阵。
> **待培训师确认**：真实拜访中电话形态到底能观察到什么。

**这不影响正确性**：D3 的 GATE-04 机制要求"该形态无法观测的维度移出分母"，
本矩阵只是给出具体的可测性判断表，且明确标注了来源性质。

## 4. 权重重分配算例

电话形态下：可评 = COM-01/02/03 + MED-01/02/03/04；不可评 = COM-04/05。

| 轨道 | 维度权重 | 可评权重和 | 归一后轨道权重 |
|---|---|---|---|
| 沟通与应变（原始 60）| COM-01 20 + COM-02 20 + COM-03 15 | 55 | 55 / (55 + 100) = **0.355** |
| 专业知识运用（原始 40）| MED-01 30 + MED-02 25 + MED-03 30 + MED-04 15 | 100 | 100 / (55 + 100) = **0.645** |

**计算规则**：
```
轨道归一权重 = 该轨可评维度权重和 / (轨A可评权重和 + 轨B可评权重和)
维度归一权重 = 该维度原始权重 / 该轨可评维度权重和
维度得分 = 原始维度分 × 维度归一权重 × 轨归一权重
```

**已验证**：端到端原型在电话形态下实际输出「话术 0.355 / 知识 0.645」，与本算例一致。

## 5. 报告呈现要求

**不可评 ≠ 0 分。** 报告必须显式区分三种状态：

| 状态 | 报告呈现 | 语义 |
|---|---|---|
| 评了，得分低 | `COM-04 临场应变：2.0` | 能力不足 |
| 不可评 | `COM-04 临场应变：本形态未评` | 证据缺失，不计入分母 |
| 未作答 | `COM-04 临场应变：未作答` | 参与度问题 |

> **实现陷阱**：把"不可评"渲染成 `0.0` 会让报告读者以为该维度得零分。
> 【本产品设计决策】一律用文字标注，不显示 0。
