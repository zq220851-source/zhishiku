# D1 · 医生画像卡 Schema

> **状态**：已冻结（Phase 0 决策包）
> **依据**：V1.3 §1.2 医生画像 / `VisitContext`；语料依据 `[A36 S28]` 沟通风格四型、`[A36 S162]`–`[A36 S166]` 七类实质异议、`[A71 S56]` 六种抗拒形态、`[A1 S5]` 科室性格、`[A42 S4]` 拜访七阶段

---

## 0. 设计立场（先说清楚，避免误用）

**画像卡是"训练情境的设定"，不是"这个医生是什么样的人"。**

三条硬约束：

1. **只描述可从语料/临床库支撑的维度**，没有依据的字段留空，不填默认值。
2. **科室性格只有一条语料依据**（`[A1 S5]`：外科/妇科喜欢直给，内科/儿科可接受绕圈），不足以支撑按科室自动生成画像。**科室维度必须人工确认，不由系统推断。**
3. **禁止画像卡携带任何医学结论**。画像卡决定"医生怎么问"，不决定"答案是什么"。医学事实由知识版本锁定（AT05）。

## 2. 字段规格

### 2.1 `communication_style.style_type`

**取值（穷举，来自 `[A36 S28]` 语料四型）**：

| 值 | 中文 | 语料特征 | 提问倾向 |
|---|---|---|---|
| `analytical` | 分析型 | 关注数据与逻辑 | 先要证据，再听说法 |
| `driven` | 驱策型 | 关注结果与效率 | 直奔结果，要结论 |
| `benevolent` | 仁慈型 | 关注关系与感受 | 温和，多问背景 |
| `expressive` | 表现型 | 关注参与感 | 爱互动，需要对话感 |

> **为什么用这四型而不是 DISC**：语料原生就是这四型，且直接对应药代拜访场景；DISC 是外部框架，语料无支撑。
> 【本产品设计决策】V1.3 §1.2 未指定分类法，选语料原生体系以保证可溯源。

**关键约束（AT05）**：风格类型只影响**措辞、语速、提问顺序**，**不影响医学内容的正确性**。
同一道题，驱策型医生和仁慈型医生听到的医学事实必须完全一致。

### 2.2 `objection_profile.primary_type`

**取值（来自 `[A36 S162]`–`[A36 S166]` 七类实质异议）**：

| 值 | 类型 | 语料示例 |
|---|---|---|
| `price` | 价格异议 | 「费用太低」`[A30 S21]` |
| `demand` | 需求异议 | 「没有病人」`[A30 S21]` |
| `power` | 权力异议 | 科室采购/进药决策权不在本人 |
| `product` | 产品异议 | 「副作用也太大」`[A36 S164]` |
| `supply` | 货源异议 | 供货/配送问题 |
| `rep` | 对药代本人的异议 | 「没听过你们公司还做这类产品」`[A36 S165]` |
| `timing` | 购买时间异议 | 「没时间的」`[A24 S65]` |

> **注意**：`rep` 类（对药代不信任）**不是产品问题，是关系问题**。语料把它单列为七类之一，说明这在真实拜访中占比不低。
> 训练时必须能识别并处理，不能当成产品异议应对。

### 2.3 `resistance_style.form`

**取值（来自 `[A71 S56]` 六种抗拒形态）**：拖延、假借理由、沉默、转换话题、反对层出不穷、倦态。

**`trigger` 字段**：触发抗拒的具体情境。这是训练难度的调节旋钮。

### 2.4 `visit_context.visit_stage`

**取值（来自 `[A42 S4]` 拜访七阶段）**：

| 阶段 | 训练含义 |
|---|---|
| 拜访前计划 | 目标设定、资料准备 |
| 开场破冰 | 建立基本信任 |
| 需求探询 | 挖出科室真实需求 |
| 介绍与说明 | 讲清产品的价值与边界 |
| 异议处理 | 应对七类异议 |
| 缔结与约定 | 「缔结时约定下次拜访的日期和时间」`[A75 S137]` |
| 跟进维护 | 长周期维护 |

> **场景种子分布**：48 条场景种子按阶段分布，训练优先级由阶段决定。

## 3. 填写规则

| 规则 | 说明 |
|---|---|
| **R1 不推断** | 系统不自动填 `style_type` / `objection_profile` / `resistance_style`。这些必须人工选定或从语料库匹配 |
| **R2 空值合法** | 无依据的字段留 `null`，并写 `note` 说明。**禁止填"平均" "一般" 这类伪默认值** |
| **R3 证据必填** | 每个非空的行为字段必须有 `evidence` 或 `source` |
| **R4 科室不自动生成** | `department_personality` 仅 `[A1 S5]` 一条语料，必须人工确认 |
| **R5 医学隔离** | 画像卡不含任何医学结论、医学数值、适应症描述 |
| **R6 可追溯** | 每张画像卡可追溯到创建者与依据来源 |

## 4. 三类来源与可信度

| 来源 | 用途 | 可信度 |
|---|---|---|
| 人工录入 | 真实医生画像 | 最高 |
| 语料匹配 | 从 `[A36 S28]` 等条目匹配 | 高（可溯源）|
| 系统合成 | 训练用虚拟角色 | **仅供训练**，必须标 `synthetic: true` |

> **合成角色必须显式标记**。端到端原型当前用的是合成角色，报告中应体现。
> 【本产品设计决策】合成角色不进入任何真实画像统计。

## 5. 字段缺口清单（诚实版）

| 缺口 | 影响 | 处理 |
|---|---|---|
| 语料科室覆盖极薄 | 无法按科室生成画像 | 科室维度全部人工确认（R4）|
| 无医生级别的真实数据 | 画像全靠人工 | 一期走"每疾病 3–5 张人工卡" |
| 无医生说话风格样本 | 风格只能靠四型 | 一期用四型，不做个体化 |
| `hospital_tier` 无语料支撑 | 无法推断 | 人工填写，规则不做默认 |

## 6. 与引擎的接口

| 字段 | 被谁消费 | 用途 |
|---|---|---|
| `communication_style.style_type` | `DoctorSim` | 决定措辞与提问顺序（**不改医学内容**）|
| `objection_profile.primary_type` | 考点选择器 | 优先匹配对应异议类型的题 |
| `resistance_style.form` | `DoctorSim` | 决定追问是否转为抗拒形态 |
| `visit_context.visit_stage` | `build_plan()` | 决定本轮考点所属阶段 |
| `visit_context.channel` | `Rubric` GATE-04 | 决定哪些维度可评 |
| `knowledge_lock.knowledge_pack_version` | 知识检索 | 锁定医学事实版本 |
