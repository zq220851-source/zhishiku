# D6 · 数据可见性与考核边界

> **状态**：已冻结（Phase 0 决策包）
> **用途**：定义「哪些数据谁能看」「错误留存怎么用」「什么指标可以用来评价一个人」
> **依据**：V1.3 §1.3 知识包版本、§2.1–2.3 复盘链路、§3 板块划分；语料 `[A42 S4]` 拜访七阶段

---

## 0. 核心立场

**课程是素材，训练计划是编排。** 一次训练不是"放一门课"，而是
**按当前能力缺口，从课程里挑出最该练的几题，按拜访阶段排成一条对话。**

这也是 V1.3 强调"题量不固定"的根本原因——**固定题量必然有一半是无关的题**。

---

## 1. 三层结构

```
课程（Course）          素材层。一门课 = 一个疾病 × 一个维度
  ↓ 题库抽取
检验题（Question）       候选层。每题带能力点、依据、核实路径
  ↓ 编排
训练计划（Plan）         按能力缺口 + 拜访阶段 + 时长预算编排
  ↓ 执行
训练会话（Session）      AI 医生多轮追问
  ↓ 评
复盘包（Debrief）        覆盖率 + 错误留存 + 改进建议
```

## 3. 训练计划生成规则

### 3.1 输入

| 输入 | 来源 |
|---|---|
| 学员能力状态 | `EmployeeSkillState`（GAP 画像）|
| 目标能力点 | 用户选择 / 上轮未覆盖项 |
| 可用题目 | 课程题库（候选层）|
| 场景约束 | 医生画像卡（阶段、异议类型、抗拒形态）|
| 时长预算 | 用户设定 |

### 3.2 编排顺序（按拜访七阶段推进）

依 `[A42 S4]` 拜访七阶段：

```
需求探询 → 介绍与说明 → 异议处理 → 缔结与约定
```

**为什么按阶段而不是按知识点排**：真实拜访是有节奏的，
把 8 个疾病的题混在一场对话里，训练就变成了知识测验，不是在练拜访。

### 3.3 选题优先级（可解释，四类）

| 优先级 | 理由标签 | 来源 |
|---|---|---|
| P0 | 员工薄弱项 | GAP 画像（近 3 次训练的扣分维度）|
| P1 | 上一轮未覆盖 | CoverageMap 的 `not_covered` |
| P2 | 场景相关（异议类型匹配）| 医生画像卡的 `objection_profile` |
| P3 | 常规轮换 | 覆盖度最低的能力点 |

**每题必须显示 `why_recommended`**（一句话理由）。

> ⚠️ **禁止**「某专家提问概率」「高频问题」这类表述——语料无频次统计支撑。
> V1.3 D05 已明确指出「高频」是无统计口径的表述，容易造成虚假频次宣称。

### 3.4 题量决策

```
题量 = min(时长预算可容纳轮次, 目标能力点数, 可用匹配题数)
```

**可解释的调整理由**（记入 `plan_meta`）：
- 「时长预算 8 分钟，按实测每轮 1.6 分钟计，扣掉开场 1 分钟 → 4 题」
- 「目标能力点 3 个，其中 1 个无已审核题目 → 实际 2 题」

## 4. 复盘包（Debrief）

V1.3 §2.1–2.3 的最小实现：

| 组成 | 内容 |
|---|---|
| **CoverageMap** | 本次覆盖了哪些能力点（`covered` / `not_covered`）|
| **错误留存** | ErrorEvent：规则 ID、维度、原文片段、扣分依据 |
| **改进建议** | 按可行动性排序（不是按分数低排序）|

**改进建议的排序原则**：**先补知识、再补表达、最后补场景应对**。
理由：知识错误会连带影响表达和应对，先补上层问题，下层问题会一起改善。

## 5. 可见性与数据边界（硬约束，不可协商）

### 5.1 药代看不到别人的错误

**药代只能看到自己的训练记录与自己的 GAP 画像。**

- 药代**不可见**同事的错误明细、扣分记录、原始回答
- 药代**不可见**任何形式的团队排名或横向对比
- 管理者**可见**自己管辖范围内的汇总与趋势

> **理由**：横向对比会直接损害陪练的自愿使用意愿。
> 一旦药代发现训练记录会被用来评价自己，工具就失去纠错价值——没人愿意在会被记录的场合暴露弱点。

【本产品设计决策】技术上：权限在 API 层强制，前端不做「能看但藏起来」的软隐藏。

### 5.2 错误留存不作为处罚依据

**训练记录不作为人事处罚依据、不作为考核依据。**

- 训练中触发的 GATE-01/GATE-02 记录，**仅用于重练池与个人改进**
- 不进入人事档案、不作为绩效或处罚依据
- 训练数据与人事系统**不做自动打通**

> **理由**：如果违规一次就可能影响绩效，药代会规避训练——系统会快速失去价值并产生合规风险。

【本产品设计决策】需在产品内显著位置声明，并由法务确认措辞。

### 5.3 考核看收敛趋势，不看单次分数

**看的是弱项是否在收敛，不是某一次考了多少分。**

单次分数受题目难度、场景难度、状态波动影响太大。
有意义的指标是：

| 指标 | 定义 | 看什么 |
|---|---|---|
| 弱项收敛 | 同一维度的扣分次数随训练轮次的下降 | 练了有没有进步 |
| 覆盖率提升 | `not_covered` 比例的下降 | 练得够不够广 |
| 高频错误复现率 | 同一规则 ID 重复触发的比例 | 有没有真学会 |

> **不作为考核依据的指标**：单次综合分、单次等级。
> 【本产品设计决策】综合分只用于**反馈**，不用于**评价**。

## 6. 复盘链路的实现缺口（诚实版）

| 环节 | V1.3 要求 | 本项目现状 |
|---|---|---|
| DebriefRaw | 原始复盘包 | ⬜ 未接 |
| Observation | 观察记录 | ⬜ 未接 |
| CoverageMap | 覆盖率图 | ⬜ 未接 |
| 人工标注回流 | 培训师补注释 | ⬜ 未接 |
| 评分校准 | 阈值经标注集校准 | ⬜ 未做（见 D3 §8）|

> **端到端原型的现状**：能产出 AssessmentReport（含 GAP 画像与建议），
> 但**未实现 V1.3 的正式复盘链路**。原型是规则引擎 + 报告生成，不是复盘系统。
