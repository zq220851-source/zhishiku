## 0. 这份基线集解决什么问题

**评分引擎的 bug 最危险的地方不是判错一道题，而是判反了。**

具体说：把「拒绝回扣」判成「接受回扣」，会把合规的药代一票否决掉。
这种错误在只看正例的测试里根本发现不了——所以基线集必须**正反成对**。

**这份基线集有三个用途**：

1. **规则引擎的单元测试**——每次改规则必须全绿
2. **培训师标注集的种子**——标注员在此基础上复核，而不是从零写
3. **D08a-4 降档阈值的回归基线**——阈值调参后跑一遍，防止改坏

| **B 否定伪装** | 3 | "这不叫回扣，这叫咨询费"——换名不换实质 |

### 1.2 语义等价层（D07-1）—— 委婉表达怎么判的

纯关键词匹配对委婉表达整类**漏判率 100%**。加词表是打地鼠（每种说法都能再变一次）。

**改为识别语用结构**：每条等价规则由两个要素组成，必须**共现**才命中。

| 结构 ID | 语用特征 | 委婉标记（举例） | 交易语境（举例） | 映射规则 |
|---|---|---|---|---|
| EQ-01 | 利益小额化 | 小心意、小意思、有点表示 | 给您、先收、不然不好办 | CR-04 |
| EQ-02 | 关系化包装 | 朋友之间、自己人、大家都是 | 心意、好处、通融 | CR-04 |
| EQ-03 | 惯例正常化 | 别的代表都这样、行业里都是 | 给、好处、安排 | CR-04 |
| EQ-04 | 规避记录 | 不用写、参考就好、别记 | 病历、上报、档案 | CR-04 |
| EQ-05 | 将来时利益 | 事成之后、到时候、回头再 | 少不了、一定给 | CR-04 |
| EQ-06 | 空间腾挪暗示 | 腾出点空间、想想办法、争取一下 | 价格、折扣、进院 | CR-03 |
| EQ-07 | 委婉索取数据 | 报一下、估个数、拉一下 | 用药量、处方量、病人 | CR-05 |
| EQ-08 | 施压转嫁 | 通融一下、高抬贵手、行个方便 | 意思、就这一次 | CR-04 |

**三个工程约束**：

1. **等价层不新增闸门** —— 只把「换说法说同一件事」映射回已有的 D2 规则 ID
2. **等价层必须做方向判定** —— 委婉标记同样会出现在拒绝语境里
   （「这点小心意我不敢收」vs「一点小心意是人之常情」含同一标记，判定相反）
3. **共现而非单词** —— 标记可在语料里枚举，语境结构稳定

**它解决的假阳性**（自测 18/18）：

| 输入 | 判定 | 原因 |
|---|---|---|
| 「这点小心意我不敢收」 | 不成立 | 拒绝语境 |
| 「看能不能给您腾出点空间」 | 成立 | 「能不能」是试探不是拒绝 |
| 「大概差不多是这个意思吧，我回头再给您确认」 | 不成立 | 「意思」在 EQ-05 中已收紧 |
| 「用药量数据我们医学部统一对接」 | 不成立 | 无交易语境共现 |

**残留局限**：语境共现仍是模式匹配，不是真正的语义理解。
对**完全不含标记词**的纯语义规避（如「让科室好写点意见」），当前仍会漏判。
→ 列入 D07-1b（需 LLM 语义判定或人工标注集验证）。

## 3. 关键样本（为什么这几条最重要）

### 3.1 CR04-02 · 拒绝回扣 ★

> 「回扣是违反国家法律和公司员工守则的，我不能答应您。」

**这是整份基线集里最重要的一条。**

- 语料依据 `[A74 S77]`「客户要求回扣，因为违反国家法律和公司的员工守则 能不能让步？」
- 这是**语料中唯一明确把拒绝回扣标为正确动作的条目**
- 若规则只做关键词匹配，这条会被误判为一票否决——**惩罚合规行为**
- 正确判定：`expect_gate = null`，`expect_direction = 拒绝`，且**应正向计分**

### 3.2 EU-01 ~ EU-05 · 委婉表达 ★★

> 「这个按规矩得有点表示，不然不好推进。」

**这类是扩样的主要收获。** 五条样本里**没有一条包含任何明确的违规关键词**，
但每一条都在实质上要求不正当利益。

| 样本 | 表达 |
|---|---|
| EU-01 | 按规矩得有点表示 |
| EU-02 | 事成之后少不了您的 |
| EU-03 | 一点小心意是人之常情 |
| EU-04 | 能不能给您腾出点空间 |
| EU-05 | 不用写进病历 |

**纯关键词匹配对这五条的漏判率是 100%。**
这说明合规判定不能只靠词表——**必须叠加语义方向判定与委婉表达的语义等价识别**。

### 3.3 CR02-02 · 披露状态 ≠ 审批状态

> 「该资产的审批状态还是未获批，披露口径是研发中，两者不能混。」

语料/临床库依据：`expanded_pipeline.approval_status` 真实值为 `research_asset_not_approved`，
`reported_status` 为研发方披露口径。**两个状态混为一谈是本项目最典型的越界错误。**

### 3.4 BR02-03 · 终点外推

> 「研究里 PFS 改善了，那生存肯定也能改善。」

**为什么要进基线集**：这是把替代终点直接外推到总生存——**真实拜访里最常见的证据越界**。
对应的反例 BR02-04「PFS 改善不能直接等同于 OS 获益」必须判为不触发。

### 3.5 UNS-01 vs UNS-03 vs UNS-07 · 不可评分的边界

| 样本 | 回答 | 期望 |
|---|---|---|
| UNS-01 | 「具体适应症我需要查一下再回复您」| 不可评分 |
| UNS-03 | 「这个数据我需要按最新披露核实之后再回复您」| **可评分** |
| UNS-07 | 「这个适应症的情况我需要查一下再回复您」| 不可评分 |
| UNS-08 | 「入组标准和终点定义我可以帮您整理出来…」| **可评分** |

**差别不在措辞，在「有没有可评的实质内容」**：

- UNS-01/07 说的是「具体适应症」——知识缺口（D0 缺口清单 G-A1：两库均不含说明书级内容），
  **系统不能判药代知识错**，整题剔除
- UNS-03/08 有实质内容，只是需要核实，**正常判分**

**这条边界如果搞错，GAP 画像会被系统自身缺口污染。**

## 4. 怎么用

```bash
python3 build_d7_baseline.py      # 构造基线集
python3 expand_d7_baseline.py    # 扩展到 103 条
python3 check_rule_syntax.py     # ★ 规则正则语法与括号平衡检查
python3 run_baseline_regression.py  # 跑引擎回归
```

**通过标准**：每条样本的实际判定与期望一致，**且豁免样本必须正向计分**。

> **`check_rule_syntax.py` 的来历**：规则用正则实现，改了几轮后反复踩括号不匹配的坑。
> 这个检查器常驻——单条规则的正则出错会让整个模块 import 失败。

### 4.1 作为培训师标注种子

标注员的任务**不是从零标注**，而是：

1. 复核基线集的期望判定（是否合理、措辞是否需要调整）
2. **重点复核 `review_needed` 的样本**（见 §5）
3. 补充标注不一致或缺失的样本
4. 对分歧样本给出最终裁定

**基线集本身 `review_status` 也是 `pending_medical_review`**——未经审核，不得直接作为评判依据。

### 4.2 作为阈值回归基线

D08a-4 降档阈值调参时：

1. 用标注集搜索最优阈值
2. 用新阈值重跑这份基线集，**结果不得变化**
3. 变化即说明阈值调参引入了回归

## 5. 需人工裁定的样本

**3 条**——这些样本的期望值本身存在解释空间，
不作为硬断言，只作为标注员的裁定入口。

| 样本 | 争议点 | 当前处理 |
|---|---|---|
| `EU-04` | 价格让步是否构成红线需合规裁定（D02-1 边界问题）；当前按不触发处理 | 按不触发处理 |
| `EU-05` | 规避病历记录归入哪条规则、算红线还是边界，需合规裁定 | 按不触发处理 |
| `ND-03` | 规则未命中即无豁免可言；本条改为验证「不触发」，期望豁免标记为误设 | 按不触发处理 |

**为什么保留而不是删掉或硬判**：

- 删掉 = 这些难例从此无人检验
- 硬判 = 把我的猜测固化成"标准"，误导后续标注
- 保留并标记 = **让有裁定权的人（合规）来决定**，同时不阻塞工程推进
