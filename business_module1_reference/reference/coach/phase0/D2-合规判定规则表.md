# D2 · 合规判定规则表

> **状态**：已冻结（Phase 0 决策包）
> **用途**：GATE-01 合规硬红线（一票否决）与 GATE-02 适用边界越界（强制降档）的判定规则
> **依据**：V1.3 §0.1 合规红线、§1.5；语料 `[A74 S77]`（拒绝回扣 = 唯一明确的正向锚点）

---

## 0. 第一原则

**这份规则表只做一件事：判定「这句话能不能说」。**

它不评"说得好不好"——那是 D3 的九维度。混在一起会导致合规问题被话术分掩盖。

**第二原则（更重要）**：这份规则表**不做法律判断**。
它是**基于语料的培训判定口径**，用于训练与自检，**不构成法律意见**，
最终以公司合规部门口径为准（见 §8 待确认清单）。

---

## 1. 两级红线的区别

| | GATE-01 合规硬红线 | GATE-02 适用边界越界 |
|---|---|---|
| **性质** | 不可协商 | 严重但非绝对 |
| **后果** | 本轮不通过，**不计入个人均分**，记入重练池 | MED-03 计 0 + **强制降档** |
| **综合分上限** | 0 | 2.5（1–5 分制）|
| **触发场景** | 承诺疗效、宣称获批、返利回扣、绝对化优越、保证效果 | 在研说成可用、研究阶段说能用、适应症断言、越界用药建议 |
| **可申诉** | 否（本轮直接不通过）| 是（可走复核流程）|

> **为什么分两级**：把"宣称未获批适应症"和"承诺疗效"同等处理会稀释严重性。
> 但也不能把所有边界问题当一票否决——有的可以补救。

## 2. GATE-01 合规硬红线（8 条）

**判定方式：文本匹配 + 语义方向判定**（见 §4）。规则 ID 供 D3 真值表与引擎引用。

### CR-01 承诺疗效 / 保证效果

- **触发**：出现「保证」「一定能」「肯定有效」「绝对有效」「确保有效」等对疗效的承诺
- **边界**：使用"数据显示/研究提示"等有来源限定的表述**不触发**

### CR-02 宣称获批 / 适应症越界宣称

- **触发**：将具体适应症说成已获批；或将研究阶段资产说成"已上市/可用于"
- **关键**：**披露状态 ≠ 审批状态**。管线资产的 `reported_status`（研发方披露口径）与 `approval_status`（审批状态，如 `research_asset_not_approved`）必须分开表述
- **正确项模板**：「该资产目前披露口径是 X，审批状态为 Y，能否作为可推广信息要看审批状态。」

### CR-03 承诺可及性 / 绕过采购与目录

- **触发**：承诺「一定能进院」「我帮你搞定进目录」「保证能用上」
- **依据**：绕过采购流程属于合规红线

### CR-04 回扣 / 返利 / 不正当利益

- **触发**：接受、承诺或暗示任何形式的不正当利益（含回扣、返点、变相利益）
- **反向项（必须识别为正确）**：明确拒绝并说明违反国家法律和公司员工守则
- **语料依据**：`[A74 S77]`「客户要求回扣，因为违反国家法律和公司的员工守则 能不能让步？」——**语料中唯一明确把拒绝回扣标为正确动作的条目**
- **⚠️ 关键**：D0 已隔离 **64 条**灰色手法（G-1 ～ G-64），全部只作识别对象，**绝不可写成推荐做法或高分锚点**

### CR-05 统方 / 处方数据获取

- **触发**：要求或暗示获取、交换医生处方数据

### CR-06 绝对化优越表述

- **触发**：「最好」「第一」「唯一」「全面优于」「彻底解决」等绝对化用语
- **边界**：有明确限定条件的比较表述（如"在 X 研究人群中，Y 组 Z 指标优于对照"）**不触发**

### CR-07 贬低竞品 / 诋毁其他企业

- **触发**：对竞品的贬损性、无依据的负面表述
- **边界**：基于可核实事实的产品比较**不触发**

### CR-08 诱导处方 / 利益诱导

- **触发**：以处方量、销量等直接利益诱导医生用药
- **边界**：合规的学术信息传递、真实-world study 邀约**不触发**

## 3. GATE-02 适用边界越界（6 条）

### BR-01 在研资产说成可用于临床

- **触发**：把在研资产描述为临床可用
- **正确项**：明确披露为研发阶段，说明审批状态

### BR-02 研究阶段结果说成临床获益

- **触发**：把研究阶段的疗效信号直接等同于临床获益，未加限定
- **教学要点**：替代终点的改善不能直接等同于总生存获益（已写入一期 8 门 CE 课程）

### BR-03 适应症断言

- **触发**：未经核实即断言某产品适用于某疾病或某人群
- **正确项**：适用范围只查最新 NMPA 说明书 + 企业合规版本，不得推断
- **依据**：临床库 `product_condition_map.link_type` 一律为 `educational_topic_not_indication`（教学主题关联，**非获批适应症**）

### BR-04 越界用药建议

- **触发**：给出具体剂量、给药方案调整、联合用药建议等超出代表职责的建议
- **正确项**：说明用药决策由医生依据说明书判断

### BR-05 超出专业范围的疾病诊断建议

- **触发**：对具体患者的诊断、治疗决策给出倾向性判断

### BR-06 混淆教学主题关联与获批适应症

- **触发**：把教学关联（`educational_topic_not_indication`）说成适应症

## 4. 语义方向判定与拒绝语境豁免（实现必读）

### 4.1 为什么这条是硬要求

**同一个词，方向相反，判定完全相反。** 这是合规判定里最常见的误判来源：

| 药代说的 | 方向 | 判定 |
|---|---|---|
| 「您给我回扣，我就帮您进院。」| **实施** | ❌ 触发 CR-04，一票否决 |
| 「回扣是违反国家法律和公司员工守则的，我不能答应您。」| **拒绝** | ✅ 不触发，属正向行为 |

**若只做关键词匹配，正确的拒绝行为会被误判为一票否决**——这会系统性地惩罚合规的药代，
是比漏判更严重的错误。因此**语义方向判定是强制的，不允许只做字符串匹配**。

### 4.2 判定要求

每条规则命中后，必须判定**语境方向**：

```
命中关键词 → 取上下文窗口（前后各 1–2 句）→ 判定方向
   ↓
方向 = 实施 / 承诺 / 默许        → 触发红线
方向 = 拒绝 / 否定 / 劝阻 / 质询 → 不成立（豁免）
方向 = 澄清（同词不同义）        → 不成立（豁免）
```

**豁免不适用于 CR-01 的部分场景**：
若药代说的是「我不能保证疗效，疗效因人而异」——这是拒绝语境，豁免，正确。

### 4.3 豁免的记录要求

**豁免必须留痕**，不得静默跳过：

```json
{
  "rule_id": "CR-04",
  "matched_text": "回扣",
  "direction": "拒绝",
  "exempt": true,
  "exempt_reason": "拒绝语境：明确指出违反法律与公司守则",
  "evidence": "[A74 S77]"
}
```

**理由**：豁免判定本身有出错可能，留痕才能复核。
若豁免后该回答仍需正面计分，应在正确项中给出肯定锚点（见 §4.4）。

### 4.4 拒绝语境的正确项锚点

**拒绝红线请求，本身应被当作正向表现**，在 COM 维度（尤其是 COM-05 情境适应、
MED-04 专业与合规）给正向分，而不是"因为提到了红线词所以扣分"。

语料依据：`[A74 S77]`「客户要求回扣，因为违反国家法律和公司的员工守则 能不能让步？」
——**语料中唯一明确把拒绝回扣标为正确动作的条目**。

**正向锚点示例**：

> ✅「这个确实不符合规定，我没法答应您。公司也有明确要求，我不能这么做。
> 但我可以把您真正关心的进院流程和学术支持方式跟您对一下，看哪条路走得通。」

三个要素：**拒绝 + 说明理由 + 提供替代路径**。

## 5. 合规反例（同词不同判）

**每条红线规则必须带反例。** 反例的作用是：证明规则判的是"行为"不是"词"。

| 规则 | 正例（触发）| 反例（不触发）|
|---|---|---|
| **CR-01** 承诺疗效 | 「这个药肯定有效，您放心用。」| 「我不能保证疗效，临床研究显示的是 X，具体要看说明书。」|
| **CR-02** 宣称获批 | 「这个已经获批用于非小细胞肺癌了。」| 「该资产的审批状态还是未获批，披露口径是研发中，两者不能混。」|
| **CR-03** 承诺可及性 | 「我保证能进你们医院目录。」| 「进目录要走医院的流程，我可以帮您了解需要哪些材料。」|
| **CR-04** 回扣 | 「您给点好处，我这边好说话。」| 「回扣违反法律和公司守则，我不能答应您。」|
| **CR-05** 统方 | 「把您这边其他科室的处方数据给我看看。」| 「处方数据涉及患者隐私，我这边不掌握也不能收集。」|
| **CR-06** 绝对化 | 「我们是这个领域最好的、唯一的。」| 「在 X 研究人群中 Y 指标优于对照，限定条件我一起给您。」|
| **CR-07** 诋毁竞品 | 「那家产品根本不靠谱，临床数据都是造出来的。」| 「两款产品定位不同，我按公开资料给您对比。」|
| **CR-08** 诱导处方 | 「您多开点，年底我给您申请奖励。」| 「您按临床需要决定，我这边提供的是学术信息。」|

**反例的工程价值**：这 8 组反例已固化为 **D7 判定回归基线集**（41 条），
每条规则的实现必须能通过正例、拒绝反例两个方向。

## 6. 判定流程

```
药代回答
   ↓
【第 1 层】逐条匹配 GATE-01 规则（CR-01 ~ CR-08）+ 语义方向判定
   ├─ 命中且方向为实施 → 本轮不通过，综合分上限 0，不计入个人均分
   │                       记录 CR-xx + 原文片段 + 进入重练池
   ├─ 命中但方向为拒绝/澄清 → 豁免，但留痕
   └─ 未命中 → 继续
   ↓
【第 2 层】逐条匹配 GATE-02 规则（BR-01 ~ BR-06）
   ├─ 命中 → MED-03 计 0，触发强制降档
   └─ 未命中 → 继续
   ↓
【第 3 层】进入 D3 的九维度加权评定
```

**执行原则**：
- 第 1 层命中即终止，不再评其他维度（红线优先）
- 但**该题仍计入分母**——因为它确实被评了（见 D3 §2.1）
- 同一回答可同时命中多条规则，**全部记录**（不只记第一条）
- **命中后必须做语义方向判定**（见 §4.2），拒绝语境豁免但留痕

### 7.2 映射的三条纪律

1. **映射表只用于「识别」，不用于「推荐」。** 灰色手法的正确处置永远是识别 + 拒绝 + 替代路径。
2. **D0 定性优先于关键词映射。** D0 已标为「历史现象记录」或「合规不隔离」的条目，
   即使命中关键词也不作违规判定——**映射表不改变 D0 的定性**。
3. **⚠️ 灰色边缘条目需人工定阈值。** D0 标为「灰色边缘，需 D2 定阈值」的条目，
   本表不自动判定，留给合规部门裁定（见 §8）。

## 8.5 规则的代码落点与共享

> **本节记录实现侧的重要约定（2026-10-31 补充）。**

### 8.5.1 规则只定义一次

| 消费者 | 文件 | 用法 |
|---|---|---|
| 评分引擎 | `medrep_coach.py` → `Rubric` | `compliance_rules.COMPILED_RULES` |
| LLM 输出校验 | `llm_provider.py` → `FactGuard` | `compliance_rules.match_rules()` |
| 规则质量检查 | `check_rule_quality.py` | 空匹配 / 尾随 `|` / 语法 / 正例可命中 |

**为什么必须共享**：开发中发现 FactGuard 独立维护了一套红线正则，
导致「给我点好处」这类变体在 FactGuard 漏判、在 D2 规则层命中——
**同一类覆盖不足在两处重复出现**。

> 规律：同一份词汇表/规则在两处定义 = 覆盖不足必然重复发生。
> 本项目已因此踩坑多次（规则层、否定词表、目录名），现已全部收敛到共享模块。

### 8.5.2 否定语境必须回看窗口，不能用正则前瞻

**实现约定**：命中位置**之前**若有否定词，则该次命中不成立。

```
「并非该药已获批的适应症」  → 豁免
「不可表述为可用于该疾病」  → 豁免
「这个已获批非小细胞肺癌」  → 命中
```

**为什么不用正则负向前瞻**：负向前瞻从匹配点**向后**看，
而否定词在匹配点**之前**——方向相反；Python 又不支持变长 lookbehind。
所以只能在匹配后手工回看窗口（`compliance_rules.has_negation_context`）。

### 8.5.3 规则质量必须可自动校验

已实现 `check_rule_quality.py`，六项检查：

| 检查 | 防什么 |
|---|---|
| 空匹配 | **尾随 `|` 造成的空分支 → 任何文本都命中该规则** |
| 尾随 `|` | 同上（根因）|
| 语法正确 | 括号不平衡 → 整个模块 import 失败 |
| ID 唯一 | 重复定义 |
| 正例可命中 | 规则写紧了永远匹配不到 |
| 等价层语境要求 | 单靠标记词误伤合规表达 |

> **开发中真实踩到**：某条正则末尾留了 `|`，产生空匹配分支，
> 结果「统方/处方数据」这条红线在完全无关的句子上也命中。
> **静默失效，不报错**——所以规则必须可自动校验，不能靠人眼扫。

### 8.5.4 检测器本身也要自测

`verify_at05.py` 自带 8 条检测器用例。实测中检测器出过一次误报
（「该关联**不属于**获批适应症」被判成宣称获批）——
**这种误报比真问题更误导人**：会让人以为 AT05 破了，去改本来正确的模型输出。
