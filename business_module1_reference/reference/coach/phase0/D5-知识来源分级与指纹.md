# D5 · 知识来源分级与指纹

> **状态**：已冻结（Phase 0 决策包）
> **用途**：定义「一个知识点能不能用于训练和评分」的判定规则，以及来源指纹
> **依据**：V1.3 §0.2「三层来源」、§1.3 KnowledgePackVersion、§2.4 复盘链路；语料「课件是培训材料 ≠ 法律依据」

---

## 0. 核心结论

**「有来源」不够，「来源的效力层级够不够」才决定它能不能当评分依据。**

最要紧的一条：**课件是培训材料，不是法律依据**。
课件里的规范性表述，效力低于法规原文——但本项目**不得用 web 搜索补法规文号**，
所以课件里的法条只能标为「培训教材所载规范」，不能标为法律依据。

---

## 1. 三层来源（V1.3 §0.2）

| 层 | 名称 | 谁能写 | 能否用于评分 | 能否进正式课程 |
|---|---|---|---|---|
| **L1 候选层** | 候选层 | 语料抽取 / 临床库导入 / 日报 | ❌ **不能** | ❌ 不能 |
| **L2 审核层** | ReviewCase 审核层 | 审核员（走 draft→auto_checked→pending_human→approved/rejected/needs_revision→published/retired）| ⚠️ approved 后可 | ✅ published 后可 |
| **L3 已审核训练层** | KnowledgePackVersion | 系统从 L2 发布的条目生成不可变快照 | ✅ **可以** | ✅ |

> **关键**：本项目所有课程与语料资产**当前全部在 L1（候选层）**，
> 医学状态一律 `pending_medical_review`。
> **未经 ReviewCase 签审，不得进入正式评分。**

## 2. 来源效力分级（本次新增，D5 的核心产出）

L1 候选层内部还要再分级，因为**不是所有候选来源的效力相同**：

| 级别 | 来源类型 | 效力 | 可否作为评分依据 | 标注要求 |
|---|---|---|---|---|
| **S1** | 法规/指南原文（含文号、版本号）| 最高 | ✅ | 【培训教材所载规范】（见下方说明）|
| **S2** | 监管批准文件（NMPA 批准文件、说明书）| 高 | ✅ | 【语料记载】+ 需核对版本日期 |
| **S3** | 已发表临床研究（可查到 DOI/注册号）| 中高 | ✅ | 【语料记载】+ 需标研究设计 |
| **S4** | 企业合规版本（内部批准话术、审批通过的宣传材料）| 中 | ✅（仅对企业自身口径）| 【语料记载】+ 版本号 |
| **S5** | 课件培训材料（讲师经验、话术模板、案例）| 低 | ⚠️ 仅作沟通训练依据 | 【培训教材所载规范】 |
| **S6** | 课件演示道具（虚构产品、模拟病例、假数据）| 无 | ❌ **绝不可** | 禁止引用为事实 |
| **S7** | 灰色手法（回扣/统方/二次公关等）| 无 | ❌ **绝不可，且必须隔离** | 仅作识别对象 |

### 2.1 关于 S1 的重要说明

本项目**禁止 web 搜索**补法规文号与指南版本。
因此：语料中出现的法条引用，其效力只能到 S5 层级，并标注为【培训教材所载规范】。

> **这不是降级凑数，是诚实标注。** 语料里写了「根据《XX法》第 X 条」，若直接标 S1，
> 等于假装我们核对过原文版本——而项目约束明确禁止这么做。
> 【本产品设计决策】S1 的准入需要**人工提供原文**（上传文件或人工录入），系统不得自行检索。

### 2.2 关于 S6：演示道具的具体清单

D0 已逐条核实，以下**是虚构演示道具，不是真实药品**：

| 标记 | 内容 | 性质 |
|---|---|---|
| `[A36 S97]` | 双氢可待因复方制剂 | 演示道具 |
| `[A36 S106]` | 智灵通 DHA | 演示道具 |
| `[A74 S79]` | ABC 与傣药 | 演示道具 |
| `[A75 S128]` | Ａ产品 | 演示道具 |

> 【语料记载】以上四项在课件中以真实产品形态出现，但实为教学演示用虚构品。
> **任何情况下不得作为药品知识进入训练。**

### 2.3 关于 S7：灰色手法的处理原则

D0 已逐条定性 **64 条**灰色手法（G-1 ～ G-64），全部隔离。

**处理原则**：
- ✅ **可作为识别对象**：用于教药代「认出这是不合规要求，并拒绝」
- ✅ **正确项锚点可用**：语料中唯一一条把「拒绝回扣」明确标为正确动作的条目是
  `[A74 S77]`「客户要求回扣，因为违反国家法律和公司的员工守则 能不能让步？」——**这条是 D2 的正向锚点**
- ❌ **绝不可**写成推荐做法、示例话术或高分锚点
- ❌ **绝不可**在评分中把「采用了灰色手法」当作高分表现

## 3. 来源指纹（Source Fingerprint）

每条进入 L1/L2/L3 的知识条目必须携带指纹，格式：

```
{source_kind}:{source_id}#{slide_or_row}@{version}:{extracted_at}
```

实例：
- 课件：`corpus:[A36 S28]@2026-01-15`
- 临床库：`clinical:med_products#sinistuzumab#v0.5`
- 临床库管线：`clinical:expanded_pipeline#asset_023#v0.5`
- 人工录入：`manual:reviewer-007#2026-02-01`

### 3.1 指纹的三个用途

| 用途 | 说明 |
|---|---|
| **可溯源** | 任一知识条目可反查到原始出处（原文、slide 号、库表行）|
| **版本绑定** | KnowledgePackVersion 绑定指纹集合，版本升级可 diff 出变化 |
| **失效检测** | 源文件更新后，指纹不匹配 → 触发重新审核 |

### 3.2 指纹的强制字段

```json
{
  "fingerprint": "corpus:[A36 S28]@2026-01-15",
  "source_kind": "corpus",
  "source_id": "A36",
  "locator": "S28",
  "source_level": "S5",
  "extracted_at": "2026-01-15",
  "content_hash": "sha256:...",
  "review_status": "pending_medical_review",
  "layer": "L1"
}
```

**缺 `source_level` 或 `content_hash` 的条目不得进入 L2。**

## 4. 知识缺口判定（→ 驱动 GATE-03）

一条知识能否用于评分，判定顺序：

```
1. 该知识点有来源吗？
   ├─ 无 → 知识缺口 → GATE-03 不可评分（整题剔除，不让药代承担）
   └─ 有
2. 来源效力 ≥ S3 吗？
   ├─ 否（S5/S6/S7）→ 仅作沟通训练依据；医学维度判为不可评分
   └─ 是
3. 经过 ReviewCase 签审了吗？
   ├─ 否 → L1 候选层，不得进正式评分
   └─ 是 → L2/L3 可用
```

> **第 2 条的关键**：课件（S5）里的医学内容，**不能用来判 MED-01/02/03/04**。
> 这会直接导致大量题不可评分——这是正确的结果，不是缺陷。
> D0 缺口清单已列 18 项，核心是 G-A1：**两库均不含说明书级内容**。
