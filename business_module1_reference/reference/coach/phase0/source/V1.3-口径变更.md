# V1.3 口径变更（2026-10-31 最高优先级）

> 依据：《MedRep_Coach_三级功能逻辑与技术开发文档_V1.3.docx》（产品方正式开发文档）
> **本文档的 4 条变更优先级高于任务拆解 v1 与原始设计稿的对应表述。**
> 其余所有要求（禁止 web 搜索、引用格式、红线、验收标准）不变。

## 变更 1 ｜评分维度命名与分项（影响 D3、D4、D7）

V1.3 的 1.5「双维能力评估」定义：

| 轨道 | V1.3 维度（以此为准） | 旧稿维度（并列标注用） |
|---|---|---|
| 沟通与应变（五维）| 问题理解、回答结构、表达清晰、临场应变、情境适应 | 拜访阶段推进、需求探询深度、异议处理质量、表达与节奏控制、合规表达边界 |
| 专业知识运用（四项）| 知识准确性、证据运用、适用边界、专业与合规要求 | 事实准确性、证据引用质量、场景适配性 |

**要求**：主用 V1.3 命名，但**保留本项目每维度已有的「典型扣分信号 + 锚点话术」**——那是 V1.3 没有的增量。两套命名并列写明对应关系，供 D4/D7 对齐。

## 变更 2 ｜题量不固定（影响 D3 及模块 2 规划）

V1.3 1.3 + 验收 AT03：题目数量可变，由「训练时长预算 + 覆盖能力点数量 + 用户选择 + 模型追问耗时」共同决定，**不能固定死 3 道**。

- 固定 3 题 → 改为可配置策略，给出上下限与选择规则
- 补**可解释优先级**机制：展示"为何推荐：与专家研究相关 / 常见培训考点 / 员工薄弱项"
- **禁止**虚构"某专家提问概率"（V1.3 0.4 明列为不在一期范围）

## 变更 3 ｜「高频」一词（影响 D2/D3/D7 表述）

V1.3 D05：「高频」词的统计口径未定义，**容易产生虚假频次宣称**。

- 无统计样本支撑前，「高频问题生成器」等表述改为**「候选训练考点」/「候选问题」**
- 在合适位置标注该口径**待拍板（D05）**
- 写清楚：语料中没有频次统计（这是事实，出处可查）

## 变更 4 ｜真伪裁判所的定位与分层（影响 D5，最重要）

V1.3 0.2 的**两个知识层次是按「审核状态」分层，不是按「来源类型」分层**：

| 层 | 内容 | 关键约束 |
|---|---|---|
| 新信息候选层 | 来源索引、论文元数据、研究摘要、前沿资讯、现场回忆与 AI 提炼 | 允许带不确定性展示，必须有清晰来源和使用限制 |
| 已审核训练层 | 获得授权和专业审批的知识卡、参考答案、题目、评分细则、训练场景版本 | **只有这一层可以进入正式评分和标准训练** |

V1.3 2.4 状态机：`draft → auto_checked → pending_human → approved/rejected/needs_revision → published/retired`
**任何 pending 项不得进入正式知识与评分；审核与发布严格分离。**

### D5 分级改为三段式

```
候选层（语料课件 + 临床库 + 日报；字段即本项目已定义的来源指纹）
   ↓ ReviewCase 签审（draft→auto_checked→pending_human→approved/rejected→published）
审核层（记录 reviewer、证据链、政策版本、结果、理由，支持撤稿影响查询与回滚）
   ↓
已审核训练层（KnowledgePackVersion，不可变快照，挂接每一次正式训练以保证回放可复现）
```

**必须明确**：语料课件与临床库条目**都属候选层，未经签审不得作为正式评分依据**。
去掉「语料层 = 主知识库」的表述。
本项目已定义的来源指纹字段**直接作为候选层字段保留**。

## 其他 V1.3 中可吸收的部分（非强制，但建议对齐）
