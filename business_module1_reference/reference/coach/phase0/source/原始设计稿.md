一、模块细化：拆到可开发、可验收的粒度
模块 1：场景配置器——“拜访谁、面对什么状态的人”
这个模块的核心不是“选参数”，而是用一组可枚举、可组合的标签，快速拼出一个足够具体的医生画像。医生不是抽象角色，他的科室、职称、年龄、性格、当下情绪共同决定了他会问什么问题、用什么语气拒绝。

1.1 科室 × 年龄范围（结构化配置，不需要“自定义”）

科室决定知识域和处方场景：心内科关注降压/抗凝/血脂，呼吸科关注慢阻肺/哮喘/抗感染，肿瘤科关注循证数据与不良反应管理，骨科关注术后镇痛与康复周期。科室选择应直接绑定该科室的高频病种、常用药物类别和拜访学术主题范围。

年龄范围作为辅助信号，影响 AI 医生的“沟通能耗”和“权威姿态”：低年资主治更可能追问细节、愿意多聊但时间碎片化；高年资主任更倾向“直接说结论、别浪费我时间”。年龄不单独决定性格，但与职称、科室风格叠加后，能显著影响问题粒度和拒绝方式。

1.2 情绪/性格标签：提供现成体系 + 允许叠加自定义

可以直接采用医药行业已有成熟基础的 DISC 四型作为默认标签底座：老虎型（D，高效决策、强势直接）、孔雀型（I，情感驱动、愿意互动但易跑题）、考拉型（S，稳健审慎、需要信任积累）、猫头鹰型（C，理性分析、追问数据和证据）。这四型在药代培训中接受度高，不需要从零发明。

在此基础上开放自定义叠加层：药代可以追加“当前情绪状态”（如忙碌/疲惫/戒备/开放）和“说话方式标签”（简洁/啰嗦/爱打断/爱反问/冷幽默）。自定义不是自由文本，而是从预设标签池中多选，避免不可控的输入导致生成质量塌陷。

1.3 联系方式与语气/口吻配置

联系方式决定练习形态：面对面拜访 vs 线上/电话沟通。两种形态对“开场破冰”“异议识别”“时间控制”的要求不同——线上更考验前 30 秒抓注意力，面访更考验非语言节奏和资料递送时机。

语气/口吻作为表现层参数，和性格标签解耦：同一个“猫头鹰型”医生，语气可以是“冷淡克制”，也可以是“耐心但步步紧逼”。口吻参数应作用于 AI 医生的文本生成风格，而不是改变知识内容。

模块产出物：一个“医生画像卡”数据结构，字段包括 科室、年龄段、DISC 主型/辅型、当前情绪标签、沟通风格标签、联系方式、语气口吻。这张卡是所有后续模块的输入参数。

模块 2：高频问题生成器——“根据画像，生成 3 个真会问的问题”
2.1 问题来源分层

高频问题不能只靠大模型凭空生成，必须有三层来源：

第一层：真实场景库（人工沉淀 + 账号绑定的历史错误数据） 。真实场景库收录的是医药拜访中反复出现的拒绝、异议和追问模式，比如“患者不多”“已经在用竞品”“你们的数据样本量太小”“这个药进了医保吗”“超适应症能不能用”。这一层保证问题的真实感和杀伤力。

第二层：科室×产品知识图谱驱动的专业追问。根据所选科室和产品，从知识库中抽取该科室医生最可能关心的循证维度：P 值/置信区间、头对头比较、不良反应发生率、特殊人群用药、医保适配性等。这一层保证问题的专业深度。

第三层：合规诱导问题（“挖坑题”） 。AI 医生需要被设定为“会主动挖坑”的角色，比如追问“这个药能不能给我爸的类风湿也用用”（诱导超适应症），考察药代是否会明确拒绝并解释原因。每一轮生成的问题中，应至少包含 0–1 个合规诱导题，根据练习阶段动态调整比例。

2.2 “三个问题”的难度组合规则

固定生成 3 个问题，但难度不平均分配，推荐配置为：

1 个常规专业问题（考察知识准确性，确保基本功过关）；

1 个异议/拒绝问题（考察情绪承接和异议处理，权重最高）；

1 个场景压力问题（合规挖坑 或 竞品攻防 或 时间压迫二选一，根据药代当前能力短板定向投放）。

3 个问题的顺序也有意义：先专业建立信任，再面对拒绝，最后处理压力。顺序本身就在训练“拜访节奏”。

模块 3：双轨评分系统——“对话质量”与“专业准确性”分开算，再合成综合评定
两个系统分开跑、分开出报告，不混在同一个模型里打分，否则“话说得漂亮但知识错了”会被话术分掩盖。

轨道 A：对话/话术 5 维度评分

5 个维度建议从医药拜访的真实失败模式倒推：

维度	考察什么	典型扣分信号
1. 拜访阶段推进	是否完成“开场—探询—呈现—异议—推进”的合理顺序	跳过探询直接讲产品；被拒绝后没有推进动作
2. 需求探询深度	是否挖出医生的临床痛点/处方障碍，而非自说自话	只问“您用不用”，不问“您这类患者目前联合用药的难点是什么”
3. 异议处理质量	面对拒绝/质疑时，是否先承接情绪、再拆解问题、再给证据	直接反驳医生；回避异议；反复重复同一句话
4. 表达与节奏控制	信息密度、重点前置、时间控制、打断应对	30 秒内没说出核心信息；被追问后逻辑散掉
5. 合规表达边界	是否守住硬红线，表述是否规范	超适应症暗示、承诺疗效、贬低竞品、提及销量/回扣等
合规维度建议采用一票否决 + 扣分双层机制：硬红线（超适应症、承诺疗效、利益诱导）触发即本轮不通过，不进入综合评定；表述不规范（绝对化用语、无出处引用）在维度内扣分并即时提示。

评分技术上可采用多 Agent 并行分析，每个 Agent 聚焦 1–2 个维度，避免单一 Prompt 过长导致各维度互相干扰；再用非线性评分因子拉开区分度，防止“人人高分”。

轨道 B：专业知识运用评分（独立系统）

不考察“说得好不好”，只考察知识调用是否准确、可溯源、适配场景：

事实准确性：适应症、用法用量、禁忌、不良反应、药物相互作用是否与权威说明书/指南一致；

证据引用质量：引用的临床数据是否标明来源、样本量、终点指标，是否存在“张冠李戴”或过度外推；

场景适配性：给这位科室、这位画像的医生讲这个知识点，是否切中其真实临床问题，还是“背了一段用不上的机制”。

专业知识评分应直接对接真伪裁判所的知识版本——如果一个问题涉及的知识点在该裁判所中没有可信来源支撑，系统应标记为“不可评分”而非强行打分，并触发知识缺口记录。

双轨合成“综合评定”

综合评定不是简单加权平均，建议采用门控合成：

专业知识轨道低于阈值 → 综合评定强制降档，无论话术多好。理由很直接：话术越好但知识错误，在真实拜访中危害更大。

合规硬红线触发 → 本轮综合评定为“不通过”，单独记录，不参与平均分“稀释”。

两条轨道均通过后，按预设权重合成综合分（建议初期话术 60%、知识 40%，随着药代资历提升逐步上调知识权重）。

模块 4：真伪裁判所——“让数据库敢被相信，也让问题敢被问出来”
真伪裁判所是整个 Agent 的可信度基础设施，它做三件事：判来源、判时效、判一致性。

4.1 数据来源分级与准入

按医药知识库的成熟实践，来源分为三级：

一级基准：NMPA 备案原版药品说明书，法定适应症、禁忌、用法用量为最高标准，任何生成内容不得偏离；

二级临床佐证：国家级临床指南、专家共识、药典、药物临床应用指导原则；

三级补充：权威医学期刊、不良反应监测官方通报。

网络自媒体、科普软文、未注明出处的“专家观点”一律不进入基准库。每一条入库知识必须携带来源指纹：来源类型、具体文献/说明书版本号、生效日期、审核人。

4.2 周更机制：不是“每周爬一次”，而是“每周做一轮差异审计”

固定节奏可以是每周一次，但核心动作是版本差异识别与替换：

监测说明书修订、新增适应症、警示语变更、指南更新、医保目录调整；

对发生变更的条目，生成“旧版 vs 新版”差异记录，旧版不删除、标记为“已废止”并保留可追溯；

任何被新版本替代的知识点，自动回溯标记受影响的场景卡、高频问题模板和评分基准。

更新周期建议：说明书/警示语类变更 72 小时内进入知识库并标记受影响场景；指南/共识类更新 1 周内完成审核入库。

4.3 多裁判交叉校验（针对生成内容，不针对静态知识）

对于大模型生成的“高频问题”和“AI 医生回应”，不能只靠单一模型判断对错。建议采用多裁判独立评分 + 一致性聚合：至少 2–3 个裁判 Agent（或不同提示变体）从“事实准确性、来源可追溯性、场景合理性”三个维度独立打分，分数离散度超过阈值的条目进入人工复核队列，而不是自动放行。这解决的是“AI 生成的问题看起来像真的，但知识内核是编的”这一核心风险。

模块 5：错误留存与账号绑定——“把每一个人的短板变成可训练的数据”
5.1 错误留存的结构化记录

每一次练习/评分中触发的错误，不能只存一条“对话日志”。需要记录为可聚合的错误事件，字段至少包括：

错误类型（知识错误 / 异议处理失败 / 合规踩线 / 表达超时 / 需求探询缺失）；

关联问题 ID 和场景画像（哪个科室、哪种 DISC 类型、哪类情绪标签下高发）；

错误发生的对话片段原文；

系统判定的具体原因（引用哪条知识或哪条规则）。

5.2 两层聚合：个体画像 + 群体共性

账号绑定层：每个药代有一个持续更新的能力 GAP 画像。不是“总分多少”，而是“在老虎型医生+异议处理场景下，合规表达边界反复出问题”这种可行动的诊断。系统据此推送定向训练任务（重练特定场景卡、推送对应知识卡片、安排专项模拟）。

组织层：聚合到一个阈值（如同一错误类型在 30 天内被 N 人触发，或单人重复 3 次以上）即自动进入集中处理队列，由内容/培训团队判断是“个体能力问题”还是“问题模板本身有缺陷/知识库有歧义”。如果是后者，反过来修正问题生成器和知识库，形成闭环。

5.3 与考核的边界

需要明确一条产品原则：错误留存用于训练分配和能力诊断，不直接作为人事处罚依据。否则药代会倾向于回避高难度场景，导致训练数据失真。考核可以看“GAP 收敛趋势”，但不看单次错误次数。

三、优先级：先做什么，后做什么
P0（没有它产品不成立） ：

场景配置器的基础标签体系（科室 + DISC + 合规诱导开关）→ 高频问题生成器的第一版（真实场景库 + 知识图谱，先不做多裁判）→ 话术 5 维度中的“异议处理 + 合规边界”两个维度 → 错误事件记录与账号绑定。先跑通“选画像 → 练 3 题 → 拿到一份能指出具体问题的报告 → 系统记住这个人哪里弱”的最小闭环。

P1（决定“敢不敢用于生产”） ：

真伪裁判所的三级来源准入 + 周更版本审计 → 专业知识评分轨道上线 → 双轨门控合成 → 多裁判交叉校验。这一层做完，系统才具备“知识可信”的底线。

P2（决定“越用越聪明”） ：

错误留存的两层聚合（个体 GAP 画像 + 群体共性集中处理）→ 定向训练任务自动推送 → 组织级数据看板 → 基于长期错误趋势反向优化问题模板和知识库。

核心判断只有一条：这个 Agent 的价值不在于“打分”，而在于让每一次练习都同时生产三样东西——一个更准的医生画像、一条更可信的知识、一份关于这个药代的具体短板记录。 场景配置和真伪裁判所决定前两样的质量，双轨评分和错误留存决定第三样能不能被用起来。分工围绕这个数据流来落，比按“功能模块”切更不容易做成四个互不相通的孤岛。
