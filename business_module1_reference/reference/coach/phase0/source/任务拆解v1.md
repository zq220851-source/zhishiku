# 药代拜访陪练 Agent — 开发任务拆解 v1

> 依据：《模块细化 / 分工 / 优先级》原始设计稿（2026-10-31）
> 版本：v1（开发可执行版）
> 核心判断：产品的价值不在"打分"，而在让每次练习同时生产三样东西——更准的医生画像、一条更可信的知识、一份关于这个药代的具体短板记录。任务拆解围绕这条数据流展开。

---

## 0. 本文档怎么读

- **任务 ID 规则**：`P<阶段>.<工作流>.<任务序号>`，例：`P1.2.3`
- **每项任务给出三件事**：交付物（做什么出来）、验收标准（怎么算做完）、依赖（谁挡着谁）
- **R/C 对应原始设计稿五条线**：产品 / 算法·数据 / 工程 / 内容·医学 / 运营·培训
- **人日**为估算值，含开发+自测，不含需求澄清与跨部门等待
- ⚠️ 标记 = 原始设计稿未覆盖、由本次拆解新增或修正的部分

### 相比原始设计稿的 6 处结构性调整

| # | 调整 | 原因 |
|---|---|---|
| 1 | 新增 **Phase 0 决策冻结**（1.5 周） | 原稿直接进 P0 开发，但门控合成阈值、合规判定规则、来源指纹字段这些是"改了要全链路返工"的 schema 级决策，必须先冻结 |
| 2 | **真伪裁判所的最小切片**（来源指纹 + 不可评分标记）提前进 P0 | 原稿把整个真伪裁判所放 P1，但 P0 的专业知识评分与"不可评分"判定都依赖它，且"不可评分"是防止冤判药代的关键 |
| 3 | P0 问题生成只挂**第一层（真实场景库）+ 第三层（合规诱导题）** | 第二层"科室×产品知识图谱驱动"需要完整准入+版本化知识库，是 P1 能力；硬做会拖慢最小闭环 |
| 4 | DISC **降级为语气层**，新增**追问三轴**（追问深度/耐心度/关注点） | 原稿用 DISC 同时驱动"语气"和"问题粒度"，会导致同一 DISC 配任何专业题生成的追问都一样，训练价值塌陷 |
| 5 | 合规维度新增**语义方向判定前置**（意图分类） | 原稿关键词式扣分会把药代的"拒绝话术"判成违规——这是最容易被试点打脸的地方 |
| 6 | 新增**形态×维度可测性矩阵** + **"不评"权重重分配** | 原稿维度 4（打断应对/非语言节奏）在电话形态下无证据可评，必须显式降级而非硬打分 |

## 1. 关键路径与依赖总览

```

  D2 合规判定规则 ─┼─→ P1.1 场景配置器 ─→ P1.2 问题生成器 ─→ P1.3 AI医生对话 ─┐
  D5 来源指纹字段 ─┘         │                                              │
                               ↓                                              ↓
                        P1.1.5 知识白名单切片                     P1.4 双轨评分(话术2维+合规)
                                                                              │
                            P1.5 错误留存 ←───────────────────────────────┘
                                                                              ↓
                                                                    P1.6 集成验收 (Gate-1)
                                                                              │
Phase 2 (8周) ── 周更审计管道 / 知识轨道 / 门控合成 / 多裁判 ────────────────┤
                                                                              ↓
Phase 3 (6周) ── 群体聚合 / 看板 / 反向优化 ───────────────────────→ Gate-3
```

> ⚠️ 关键路径上的**日历时间**（非人日）必须单独排：Phase 1 试点 4 周、Phase 2 SLA 验证 ≥4 周、Phase 3 A/B 观察 3 周。这三段加起来 11 周，占总工期的 42%，且压缩它们等于让验收判据退化为自评。

**最长单链**：`D5 来源指纹 → P1.1.5 白名单切片 → P1.2.5 引用校验 → P1.4.4 合规判定`
**最高人力风险**：`P1.4 双轨评分`（算法侧单点，见 R1）
**最长前置项**：`P1.2.2 首批场景库沉淀`（需一线药代参与，Phase 0 就要启动采集，不能等）

## 2. Phase 0 — 决策冻结（1.5 周）

> 目标：把"人话描述的规则"变成"机器可判定的枚举/布尔条件"，并建立回归基线。此阶段不写业务代码，但产出物是后续所有 schema 的输入。

| ID | 任务 | R / C | 交付物 | 验收标准 | 人日 |
|---|---|---|---|---|---|
| D1 | **医生画像卡 schema v1** — 在原稿字段（科室/年龄段/DISC 主辅型/情绪/沟通风格/联系方式/语气）基础上新增：追问深度（给结论·要机制·要原始数据）、耐心度（打断·听完）、关注点（疗效·安全性·费用流程），并声明 DISC 仅作用于语气层 | 产品 / 算法·医学 | `DoctorProfile` JSON Schema + 字段语义说明 | ① 每字段可枚举、有取值域、有默认值；② 枚举值通过一线药代可理解性测试（N≥10，正确率≥80%）；③ 有一份"同画像两个问题生成结果不同"的样例，证明追问三轴确实生效 | 4 |
| D2 | **合规判定规则表** — ① 硬红线清单（超适应症暗示/承诺疗效/贬低竞品/利益诱导/销量回扣，逐条给正例+反例）；② 语义方向判定规则（同一表述处于"提议/接受"语境才成立，"拒绝/否定/劝阻"语境不成立）；③ 意图分类标签集 | 产品 / 法务·医学 | `ComplianceRule` 规则表 + `IntentClass` 标签集 | ① 每条红线 ≥5 正例 + ≥5 反例；② 反例必须包含"拒绝话术中含敏感词"这一类（例：药代说"回扣这个我们真不能谈"应判**合规**）；③ 法务书面确认 | 5 |
| D3 | **双轨门控合成规则** — ① 知识轨道阈值 → 降档步长表；② 合规一票否决后该轮**是否计入个人均分**（建议：不计入，记入重练池，组织层单独统计合规事件率）；③ 权重公式（初始话术 60/知识 40，随资历上调，上调条件与频次） | 产品 / 算法 | `ScoringGate` 规则文档 + 参数表 | ① 每条分支可用真值表穷举，无歧义；② 用 20 组人工标注样本跑，合成结论与人工判断一致率 ≥90% | 3 |
| D4 | **形态×维度可测性矩阵** — 逐维度标注在面访/线下面试/线上电话三种形态下的证据来源（文本·ASR 转写·时间戳），不可测维度标"不评" | 产品 / 算法·运营 | 可测性矩阵表 | ① 5 维度 × 3 形态全覆盖；② 不可测项明确写出降级后的权重重分配公式 | 2 |
| D5 | **知识来源分级准入规则 + 来源指纹字段** — 一级 NMPA 说明书 / 二级指南共识药典 / 三级期刊与官方通报；自媒体与无出处"专家观点"不入库。定义来源指纹字段 | 医学 / 算法·产品 | `KnowledgeItem` 结构 + `SourceFingerprint` 字段定义 | ① 每条指纹含：来源类型、文献或说明书版本号、生效日期、审核人、原文定位；② 自媒体/科普软文有明确的拒绝入库判定；③ 医学审核人签字 | 4 |
| D6 | **数据可见性与"不作为处罚依据"原则** — 错误留存的可见范围、单次错误次数不进入考核、药代不得被显示其他同事错误、组织层看板只见聚合不见个人明细 | 产品 / 法务·运营 | 数据可见性规则文档 | ① 法务确认；② 逐条对应到具体权限规则（谁能看什么）；③ 考核侧明确"只看 GAP 收敛趋势，不看单次错误次数" | 2 |
| D7 | ⚠️ **判定回归基线集** — 30 条标注样本（10 正例违规 / 10 反例含敏感词的合规拒绝 / 10 边界模糊），作为后续所有判定逻辑的回归测试基准 | 算法 / 医学 | `baseline_eval_set.jsonl` | ① 样本双人独立标注，不一致由第三人裁定；② 标注一致性（Krippendorff α）≥0.8 | 3 |

**Phase 0 出口条件**：D1–D7 全部冻结并签字；D7 基线集通过率可作为后续任何改动的前后对比基准。

## 3. Phase 1 — P0 最小闭环（10.5 周：开发 7 周 + 试点 4 周）

> 目标（对应原稿 P0）：跑通"选画像 → 练 3 题 → 拿到一份能指出具体问题的报告 → 系统记住这个人哪里弱"。
> 范围收敛：只做话术轨道中的 **异议处理 + 合规边界** 两个维度（原稿 P0 口径）；专业知识轨道不在 P0。

## 6. 里程碑与验收门

| Gate | 时点 | 放行条件 | 不通过的处置 |
|---|---|---|---|
| **Gate-0** | Phase 0 末（+1.5 周） | D1–D7 冻结签字；判定基线集一致性 α≥0.8 | 延长 Phase 0，**禁止进入开发**——schema 级返工代价远高于此 |
| **Gate-1** | Phase 1 末（+12 周） | 最小闭环跑通；≥80% 试点者认为报告指出了真没意识到的问题；合规反向用例零误判 | 优先修 P1.4.2 与 P1.4.5，其余可带病上线内测 |
| **Gate-2** | Phase 2 末（+20 周） | 知识可信度达标；多裁判一致性阈值在真实分布上成立；SLA 达成率 ≥90% | 知识轨道可延后，但专业知识评分不得用"无来源数据"凑数上线 |
| **Gate-3** | Phase 3 末（+26 周） | GAP 收敛趋势可量化；知识缺口率进入可治理区间 | 维持内部使用，不扩大范围 |

> ⚠️ **Gate-1 的日历时间不是人日**：开发 7 周 + 试点 4 周 + 验收 1 周。试点期（20 人 × 4 周）不可压缩——"报告是否真的指出问题"只能靠真实使用者验证，缩短试点等于把 Gate-1 的判据变成自评。
