# 课程培训可行性评估 —— K12 课程学习插件 × 医药培训场景

> 评估对象：`k12-course-learning` 插件（recall-k12-taxonomy / study-tutor / visualize-k12-concepts）
> 场景：药代拜访陪练 Agent 的知识培训与课程设计
> 结论：**可做，但需改造数据层与领域层；工具层（离线课件生成器）整套可复用。**

---

## 一、结论速览

| 维度 | 判断 | 依据 |
|---|---|---|
| 工具层（离线课件生成器） | ✅ **整套复用** | 已用真实临床库数据实测跑通，生成 53KB 单文件、0 外部运行时依赖的培训课件 |
| 教学法层（先预测→操作→讲解→检验→闭卷回忆） | ✅ **直接适用** | 该教学法对医代培训同样成立：先做判断、动手验证、听讲解、测检验、闭卷复述 |
| 领域层（K12 学科分类体系） | ❌ **不可用** | 内置 taxonomy 是中小学数理化，医代培训需自建临床能力树 |
| 数据层（K12 教材） | ❌ **不可用** | 需替换为「课件语料库 + 临床知识库」双源 |
| 学习者画像 | ⚠️ **需改造** | 原为"学生年龄+年级"，医代是"入职时长+职级+既往短板" |

**一句话结论**：把 K12 插件当**课程制作引擎**用（这是它最强的部分），把**知识体系和数据**换成医药的。别把它当现成产品用。

---

## 二、实测证据

### 2.1 已跑通：真实临床库数据 → 培训课件

用信达临床知识库的 NSCLC（非小细胞肺癌）数据，按插件的 lesson-spec 契约生成课件：

- **产物**：`training-poc/index.html`，53,846 字节，**0 个外部运行时依赖**（唯一 http 是来源标注，非运行时资源）
- **教学元素完整**：4 张分型对比卡、2 条误区纠正（PD-L1 阳性≠免疫治疗适用 / 在研≠获批）、2 道带解析的检验题、闭卷回忆题、来源与边界标注
- **合规意识内建**：每张对比卡都含"合规提示"字段（不说绝对化表述、机制讲解不外推为疗效、竞品不贬低、研究阶段≠上市状态）
- **生成器契约严格**：拒绝缺失字段（`visual.items` / `recall.hint` / `sources[].detail` 均被拒），错误信息精确可定位

### 2.2 插件能力清单（实测）

**可视化模式 5 种** —— 对医药培训的适配度：

| 模式 | 医药培训用途 | 可用性 |
|---|---|---|
| `process`（3–7 阶段） | 拜访 7 阶段流程、异议处理 4 步（缓冲→探询→聆听→答复） | ✅ 直接可用 |
| `comparison`（2–4 项对比） | 分型对照、竞品维度对比、在研 vs 获批 | ✅ 直接可用 |
| `concept-map`（3–9 节点，prerequisite/core/unlock） | 疾病→靶点→药物→终点 的知识依赖图 | ✅ 直接可用 |
| `number-line`（滑块） | 治疗线次、剂量区间、分期跨度 | ⚠️ 语义需重定义 |
| `fraction` | 罕见：应答率/客观缓解率这类比值 | ⚠️ 表达力弱，慎用 |

**taxonomy 检索脚本**：`taxonomy_recall.py` 支持 `--subject/--domain/--age/--type/--limit`，输出含 `prerequisites`/`unlocks`/`hard`/`soft`/`reason` 的知识图谱。
→ **工具可直接复用**：只需把内置 K12 topics 换成医药能力树，检索与图谱逻辑不必改。

**打包约束**：插件强制离线（禁止 CDN/远程字体/埋点/认证），单文件自包含。医药合规场景下这是**硬需求而非限制**——内部培训材料不应外传。

## 三、必须改造的四件事

### 3.1 换掉 K12 学科分类体系 → 建"医药能力树"

K12 taxonomy 是中小学数理化（`Marble Skill Taxonomy`），医代培训需要的是：

```
治疗领域（6）→ 疾病/训练主题（42）→ 能力维度（5）→ 具体知识点
信达数据: therapeutic_areas / clinical_conditions / competency_items
```

**好消息**：临床库的 `clinical_conditions.competency_scope` + `competency_items.dimension` 已经是现成的能力树雏形。

| competency_items 维度 | 数量 | 语义 |
|---|---|---|
| `disease_foundation` | 42 | 疾病基础：分型、诊断、标志物 |
| `treatment_landscape` | 42 | 治疗格局：机制类别与适用边界 |
| `clinical_evidence` | 42 | 证据解读：设计、人群、对照、终点 |
| `pipeline_literacy` | 29 | 管线认知：在研 vs 获批 |
| `product_basics` | 20 | 产品基础：通用名、机制、状态 |

### 3.2 学习者画像从"年龄"改为"岗位画像"

| K12 原字段 | 医药版替换 | 依据 |
|---|---|---|
| `age` | `seniority`（入职时长/职级） | 药代培训分层靠从业年限与职级 |
| `subject` | `therapeutic_area` | 治疗领域是医学内容主线 |
| 先修知识 | `gap_profile`（来自错误留存的 GAP 画像） | Phase 0 模块 5 的产出，可直接驱动课程难度 |

### 3.3 "答对/答错"改为"合规性与专业性双轨"

K12 的检验题是单一答案。医代场景必须双轨，且**合规一票否决**：

| 判定 | 处理 |
|---|---|
| 专业内容错误 | 维度扣分 + 知识缺口记录 |
| 合规红线触碰 | 一票否决，本轮不通过（不计入均分） |
| 系统知识缺口 | **不判分**，剔除出分母 |

第三类是 K12 场景不存在的，也是 Phase 0 反复强调的。

### 3.4 课程主题要从"知识点"升到"拜访场景"

K12 课件教概念；医代培训教**在对话压力下应用概念**。所以：

- 课件语料库提供**场景外壳**（真实异议原话、6 种抗拒形态、拜访 7 阶段）
- 临床知识库提供**内容内核**（分型、机制、终点、证据边界）
- 两者拼起来才是完整的培训单元

## 四、双库能力对照：Phase 0 缺口能填多少

D0 产出的 18 条缺口清单，与临床知识库逐条核对：

| 缺口 | 临床库是否覆盖 | 说明 |
|---|---|---|
| G-A1 临床产品知识 | 🟡 **部分** | `med_products`(20) + `med_claims`(33) 有通用名/机制/状态，但**边界说明明确写着"具体药品适应症以最新说明书审核"**——不是说明书级 |
| G-A2 真实临床数据 | 🟡 **部分** | `sources`(52) 带 URL + asof_date + 置信度；`cases`(111) 是"训练主题"而非逐字对话 |
| G-A3 科室×病种×药物类别 | 🟢 **覆盖** | `clinical_conditions`(42) + `product_condition_map`(43) + `therapeutic_areas`(6) |
| G-A4 医保目录与支付政策 | 🔴 **未覆盖** | 临床库无此维度 |
| G-A5 限方/处方限制政策 | 🔴 **未覆盖** | 临床库无此维度 |
| G-B1 法规文号现行有效性 | 🔴 **未覆盖** | 临床库 `clinical_sources` 是医学教育来源，不是法规依据 |
| G-C1 医生画像行为化证据 | 🔴 **未覆盖** | 需一线药代采集 |
| G-D1 线上形态话术 | 🔴 **未覆盖** | 课件语料只有电讯约见 |

### 4.1 关键发现：两个库的评分维度只有部分重叠

Phase 0 的 5 个话术评分维度 vs 临床库 `cases.rubric_dimension`：

| Phase 0 五维 | 临床库覆盖 | 补位来源 |
|---|---|---|
| 需求探询深度 | 🟢 23 例 | — |
| 异议处理质量 | 🟢 26 例 | — |
| 拜访阶段推进 | 🔴 无 | 课件语料 `A42 S4` 7 阶段 / `A8 S68` 9 步 |
| 表达与节奏控制 | 🔴 无 | 课件语料 `A71 S56` 抗拒形态（拖延/沉默/倦态） |
| 合规表达边界 | 🔴 无 | 课件语料 `A30 S21` 常见异议 + D2 规则 |

**结论**：两库是**互补而非替代**关系，必须双源接入。这正好印证 D5 采用的"语料层 + 临床层"双层结构。

## 五、落地路径建议

### 阶段一：立刻可做（不依赖任何改造）

1. 用 `visualize-k12-concepts` 生成器 + 临床库数据，产出**疾病基础课**（42 个 `disease_foundation` 条目）
2. 每课覆盖一个 `clinical_conditions`，视觉用 `comparison` 或 `concept-map`
3. 产出物形态与 K12 一致：单文件离线 HTML，可直接分发

### 阶段二：需要轻度改造

4. 把 `meta.age` → `meta.seniority`，`meta.subject` → `meta.therapeutic_area`
5. 用 `taxonomy_recall.py` 的图谱逻辑检索**临床能力树**（替换 topics.json）
6. 检验题从单选改为**双轨判定**（合规 + 专业），接入 D2/D3 规则

### 阶段三：与陪练 Agent 打通

7. 课件的"闭卷回忆"环节 → 陪练 Agent 的一次**知识轨道练习**（轨道 B）
8. 课件的"误区纠正" → 陪练 AI 医生**主动挖坑**的诱导题设计依据
9. GAP 画像 → 课程推荐引擎的输入，实现"越练越懂你"

---

## 六、必须提醒的三条边界

1. **临床库 175 道题目全部是 `pending_medical_review`，`grading_mode` 全为 `human_rubric_required` / `source_grounded_human_review`** —— 一道都不能直接进自动评分。README 自己也写明："培训师应完善标准答案、正反例、引用版本和分值后再启用自动评分。"

2. **`product_condition_map.link_type` 全部是 `educational_topic_not_indication`** —— 产品与疾病的关联是**教学主题关联，不是获批适应症**。任何课件都不能表述为"该药获批治疗该疾病"。

3. **临床库的 `expanded_pipeline` 覆盖 29 个在研资产，`reported_status` 与 `approval_status` 分列** —— 在研 ≠ 申报中 ≠ 已获批，三者必须在课程里严格区分，这是合规红线。
