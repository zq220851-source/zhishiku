# 医院拜访语音演练 · 外部 API 试用版

医生开场、每轮接话和会后六维评分**只走外部模型 API**，没有本机模型、模板回复或静默降级。默认接入 OpenAI Next Credits 的国产模型 `deepseek-v4.1-flash`；也可选其他 Chat Completions 兼容接口。

在项目根目录安装语音依赖并启动（macOS / Linux）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r voice-demo/requirements-voice.txt
.venv/bin/python voice-demo/server.py --port 8768
```

打开 `http://127.0.0.1:8767`，在“连接 Credits 模型”栏填入完整的 `sk-` 开头 API Key，点击“验证并连接”。验证成功后无需重启即可开始。密钥由本机服务发往 Credits，用于验证和后续模型调用；仅保存在服务器进程内存中，重启后需要重新填写，不会保存在浏览器或项目文件中。也可预先设置 `OPENAI_NEXT_API_KEY` 环境变量。默认请求 `https://api.openai-next.com/v1/chat/completions`，模型 ID 为 `deepseek-v4.1-flash`。旧版 `gemini-3.8-flash` 在实际验证中返回 `empty_response`；本机 Python 还需可用的系统 CA 证书，代码已处理 macOS 的 `/etc/ssl/cert.pem`。用户先前提供的 UUID 形态字符串返回 HTTP 401。请勿把密钥发到聊天里。

此版是“浏览器录音 → Credits Qwen Omni 转写 → 远程文本模型 → 在线普通话语音合成”的轮流对话，不是 WebRTC 全双工语音。医生台词由 DeepSeek 生成，再由 [edge-tts](https://github.com/rany2/edge-tts) 调用 Microsoft Edge 在线语音服务**逐字朗读**；可选择四种中国大陆普通话音色并试听。医生台词会发送到该语音服务，音频只在浏览器临时播放，不持久化。若语音依赖缺失或服务不可用，页面保留文字，不会切到读音不确定的浏览器默认音色。此方式适合演示；正式产品应换成有服务协议和稳定性保障的 TTS API。Credits 公开可用模型列表未列出 `qwen3.8-omni-flash-realtime`，其快速接入页只说明了 Chat Completions / Anthropic 接口，因此不能把这个实时模型名直接填入本接口。

若使用 MiniMax：

```bash
export MEDREP_API_PROVIDER=minimax
export MINIMAX_API_KEY='你的密钥'
.venv/bin/python voice-demo/server.py --port 8768
```

若使用 OpenAI：

```bash
export MEDREP_API_PROVIDER=openai
export OPENAI_API_KEY='你的密钥'
export MEDREP_CHAT_MODEL='你有权限使用的文本模型名'
.venv/bin/python voice-demo/server.py --port 8768
```

其他兼容接口设置 `MEDREP_API_PROVIDER=custom`、`MEDREP_CHAT_API_KEY`、`MEDREP_CHAT_API_URL`、`MEDREP_CHAT_MODEL`。API 缺失时页面清楚提示所缺配置，不允许进入假的“生成式医生”会话。医生调用失败时，已提交的代表发言仍保留在逐字稿；界面提示失败并暂停连续收音。

Credits 模式由浏览器录制单声道 PCM WAV，说话过程中上传递增音频片段给 Qwen Omni 转写；没有本机识别模型。每个上下文窗口最长约 24 秒；窗口内新转写校正旧草稿，音频仅临时处理、不落盘。其他文本提供商暂使用浏览器语音识别，页面也保留文字输入。医生接话由角色卡、内部关注点、最近对话和远程模型生成，允许随药代内容变化；提示词要求医生接话、陈述、表达保留和顾虑，而不是每轮提问，非流式旧接口在连续问句时会重试一次；新版流式通道不在已播报后重写台词。生成后的医生话语会拦截显见的未核实医学断言；这一层不是完整医学审核。

会后评分调用同一外部 API，读取 `scorecards/medrep-dialogue-v0.1.json` 六维行为锚点。每个非 NA 维度必须引用药代原话和轮次，服务器会逐字核对；医学产品事实因缺现行批准说明书固定 NA。报告展示来源 ID、锚点和待人工审核状态，不设总分、权重或及格线。药代可修订浏览器转写并重算。

2026-10-31 本机实测：DeepSeek Flash 的接口验证、医生开场、接话和六维评分均成功；评分约需半分钟，具体延迟随网络与模型负载变化。医生回复也不是实时全双工语音，存在转写、文本生成和语音合成的等待。

当前是训练原型，不是信达官方评分量表。会话只保存在 Python 进程内存；不持久化音频。代表录音经 Credits 发送给 Qwen，医生台词发送给 Edge 在线服务；提供商的数据处理政策仍适用。

### 5 秒停顿与实时转写修复

- 用音频帧累计连续静音时长，显示 0–5 秒进度；继续说话清零。稳态背景噪声会更新噪声门槛，避免底噪使会话一直不结束。音量门槛仍是启发式检测，复杂人声背景需要真机验证。
- 在说话过程中每约 3 秒或短停顿时发送包含前文的音频快照，逐步展示云端识别草稿。转写逐个调用，同一窗口尚未发送的旧快照由新快照替换；旧结果不会覆盖更新结果，同一窗口文字不会重复拼接。长发言使用 24 秒窗口，不会因录音分段提前让医生接话。
- 停顿满 5 秒后等待最新转写完成，再自动提交给医生；回复与语音合成另有耗时。此处“实时转写”是分段更新，不是逐字低延迟流式 ASR。草稿显示意味着识别结果已返回，“已提交给医生”才表示进入医生回应流程。
- 识别失败不会只拿成功的半段自动提交。已识别文字保留供修订；暂停、结束和新会话会取消旧请求。
- 自动用例涵盖精确 5 秒、4.9 秒恢复讲话、稳态底噪、40 秒长句、乱序、过时快照、失败与取消。真实云端接口用合成中文音频验证；不替代用户设备麦克风及实际医院噪声测试。

本次更新的 16 项前端用例通过。真实接口短音频曾成功自动生成医生回复；较长音频验证出现空转写和网络超时，已加草稿保护与 45 秒客户端超时。尚不能保证停顿第 5 秒即播放医生首音，也不能宣称逐字实时识别。
