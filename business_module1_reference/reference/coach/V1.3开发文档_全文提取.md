
# MedRep Coach｜三级功能逻辑与技术开发文档 V1.3
项目定位：面向药企内部医药代表专业学术交流培训的 AI 系统
核心逻辑：前沿预测（具体交流预演）→ 反馈进化（可信经验回流）→ 改善下一次预测与训练；每日前沿日报独立提供医学新信息与可审核的交流切入点。
文档日期：2026-10-31
文档性质：需求现状梳理 + 待决策事项 + 技术实施建议；不是已获审批的最终 PRD、医学标准或生产实施承诺。
版本范围：3 个一级板块、15 个二级模块。医生情绪/性格/语气、开放式追问和双评分属于原有训练能力的增强，不单独新增一级板块；不固定“3 道题”。
阅读标识：[已定] 表示当前讨论中已明确的产品意图；[待定] 表示仍需产品/医学/培训/合规共同确认；[建议] 表示为便于开发提出的可选实现和默认机制。本文不会把建议冒充既定需求。

## 0. 执行摘要

### 0.1 三个板块的职责边界

[TABLE 0]
一级板块 | 核心回答 | 主要输出 | 不负责什么
01 前沿预测 | 针对这次交流，应该准备和练习哪些专业问题？ | 专家学术背景线索、候选考点、预演方案、训练结果 | 不在每次对话里重复跑一轮最新文献/前沿新闻发现；不承诺预测真实专家说话内容
02 反馈进化 | 哪些真实问题可能没有练到，系统如何可靠地改进？ | 用户确认的复盘、差异候选、审核结论、场景新版本、个人复训 | 不把员工回忆直接当成医生真实言行；不让模型自行改写正式医学标准
03 每日前沿日报 | 今天相关领域出现什么新信息，有什么可了解、可讨论的话题？ | 可溯源日报、审核状态、学术交流切入点、知识候选 | 不自动将未经审核的新研究变成正式学术话术、标准答案或评分依据

### 0.2 两个知识层次和一项共享能力
新信息候选层：来源索引、论文元数据、研究摘要、前沿资讯、现场回忆与 AI 提炼。允许带不确定性展示，必须有清晰来源和使用限制。
已审核训练层：获得授权和专业审批的知识卡、参考答案、题目、评分细则、训练场景版本。只有这一层可以进入正式评分和标准训练。
共享“真伪裁判所”：逻辑上放在反馈进化板块 2.4，但实际作为三板块共享的审核/裁判服务，包含来源、主张、授权、冲突、审核和审计。

### 0.3 最小闭环（建议作为一期演示）
选择科室/专家/交流主题，读取已审核知识快照及目标专家可核实的公开研究线索。
生成数量可变的候选训练考点；用户或系统根据当前任务形成演练计划。
模拟医生按知识边界和角色风格动态提问、追问，输出双系统评价与具体能力缺口。
真实交流后，代表用语音/文字提交事件复盘，确认机器提取的事实、回忆和推测。
系统将“本次准备过的考点”与“用户报告实际遇到的专业问题”比对，提出待审核的新增考点。
经专业审核后发布场景 V2；下一次预演能看到新增考点与变更原因。
日报每天独立抓取/生成，周度审核可推动知识库版本升级，但日报未审内容不能跳过审批进入正式训练。

### 0.4 产品已知前提与不在本期范围内的事项
[已定] 内部培训用途；按具体拜访任务选择准备内容；可配置模拟医生的沟通情境；专业事实独立于角色风格；沟通应变与专业知识运用两套评价；个人错题/弱项关联员工账号；每日前沿日报；知识按周期发现、经审核后更新。
[不在一期范围，建议] 全国完整专家画像、真实医生行为预测概率、自动抓取所有论文全文、未经授权的实际拜访录音、真实医生人格定性、无需人工参与的医学知识自主发布、企业 CRM/销售漏斗、模型权重自动微调、复杂多 Agent 自治网络。

# 一、前沿预测（01）
业务主链：任务配置 → 专家背景线索 → 问题候选与优先级 → 可执行演练方案 → 模拟交互 → 双维评分 → 学员能力记录。
板块输入：用户目标/科室/专家/交流背景 + 已审核医学知识/题库/历史案例 + 个人能力历史。
板块输出：PredictionPlan、SimulationSession、AssessmentReport、EmployeeSkillRecord。

## 1.1 拜访对象与场景配置
目标：让系统明确“为哪次学术交流训练、模拟什么样的沟通情境”。
1）我们现在的设计 [已定]
用户选择医院、科室、专家等具体拜访对象，或至少选择科室和场景进入模拟。
模拟医生可配置年龄范围、情绪标签、性格、口吻、语速、追问风格等；允许自定义情境。
个性化角色属于训练场景库的“情境适应训练系列”，不是新增独立主流程。
2）缺口 [待定]
是否强制提供医院或专家？只知道科室、尚无明确专家时能否训练？
是否需要选择产品/疾病/研究主题？与科室冲突时谁决定专业边界？
角色属性究竟只改变表达与压力，还是也影响问题难度、数量、选题？
自定义标签如何限制过于极端、无法评价或对真实专家构成未经证实画像的描述？
预演是否有“快速开始/深度训练”两种任务粒度，需产品确认。
3）下一步技术制作 [建议]
VisitContext 保存 department_id、hospital_id?、expert_ref?、topic_ids[]、product_scope_ids[]、goal_text?；空字段明确标注为未提供。
RolePreset 独立保存 emotion、intensity、communication_style、speech_style、interruption_level、persona_origin=synthetic；不得隐式继承为真实专家档案。
前端配置页采用“拜访目标”和“模拟风格”两组控件；服务端做科室/产品/使用权限校验；配置变更要保留会话快照。
输入：配置 JSON；处理：验证、身份关联、冻结版本；输出：TrainingContextSnapshot；异常：专家未找到→降级为通用科室训练，不伪造专家画像。
验收：同一个训练知识包切换情绪后，关键医学事实和评分依据不变化；只有科室也能按明确的降级模式建训练任务。

## 1.2 专家学术画像
目标：从真实公开学术活动中提炼可核实的专业关联线索，而非猜测医生的性格/个人立场。
1）我们现在的设计 [已定]
关联专家公开发表研究、学术方向及可核实的公开专业信息。
已审核的历史交流案例可作为训练候选来源，但应标记为现场报告而非公开事实。
专家画像是任务级参考信息；不是全量文献数据库的替代品。
2）缺口 [待定]
同名作者、单位变更、共作者、论文署名如何确认属于目标专家？
如果只检索到论文摘要/作者列表，哪些细节可以展示，哪些必须标注无法核验？
专家学术主题与本次产品/疾病领域如何计算关联？历史报告可否显示在专家详情里？
无公开资料或身份存在歧义时，界面如何表达“未知”而非编造关联？
3）下一步技术制作 [建议]
建立 ExpertRef（候选身份）、ExpertEvidenceLink（论文与专家关系、核对状态）、TopicAffinity（主题关联及证据）。
从 PubMed/OpenAlex 等获取作者和论文元数据，优先采用机构、作者标识、研究题目和人工确认进行消歧；模糊命中不自动确认为本人。
通过“证据卡”展示：研究主题、PMID/DOI、日期、文献类型、关联原因、身份核验状态。
输入：专家名称及机构/科室上下文；处理：候选检索→身份消歧→主题聚类→证据映射；输出：有来源的专业背景线索；异常：无法核实→显示“未核实”，仅使用通用科室知识。
验收：同名作者冲突时不能自动绑定；每一个专家相关结论都有公开来源或明确的“未经核验”标记。

## 1.3 专业问题预测
目标：从已知线索中选择值得准备的专业问题，而非声称精确预测真人下一句话。
1）我们现在的设计 [已定]
依据科室/交流主题、专家公开学术背景、已审核专业知识与历史真实问题生成候选。
题目数量不固定；可包含基础知识、证据追问和临床证据适用边界等层次。
员工已有弱项可以影响个性化训练，但不应混淆为医生必然会提出的问题。
2）缺口 [待定]
“预测”是排名、主题覆盖还是概率？目前没有真实标签支持“某专家下次必问”的概率估计。
专家关联度、常见程度、专业风险、员工弱项如何组合排序？
问题数根据时间、目标覆盖率、难度还是用户选择确定？何时停止生成？
“高频”有无统计样本；没有来源时能否展示“高频”字样？
不同问题共享相同能力点时如何去重？低证据支持的前沿问题是否可进入正式练习？
3）下一步技术制作 [建议]
建立 SkillTaxonomy、QuestionCandidate、PredictionPlan：问题必须关联 skill_ids[]、evidence_ids[]、selection_reasons[]、source_types[]、review_status。
先用确定性过滤：学科/产品权限→知识状态→主题关联→历史案例关联；再用 LLM 做候选问题改写和覆盖分析；相似度去重。
使用可解释优先级而非虚构精确预测概率，展示“为何推荐：与专家研究相关/常见培训考点/员工薄弱项”。
动态问题量建议先作为可配置策略：训练时长预算、覆盖能力点数量、用户选择和模型追问耗时共同决定；具体上下限等产品确认。
输入：场景快照 + 审核知识快照 + 能力档案；输出：可追溯的候选题和优先级；异常：证据不足→不自动生成医学结论型标准答案。
验收：问题数量可变；没有频次数据时不标“高频”；任何正式考题均有有效审查依据。

## 1.4 AI 实战模拟演练
目标：将候选考点组织为有训练目标、会推进、可结束的专业学术交流模拟。
1）我们现在的设计 [已定]
模拟医生进行多轮语音对话、连续专业追问和情境变化。
情绪/性格/年龄设定影响交互方式，不得改变同一审核知识包的医学事实。
演练可包括多个主问题及其追问，不固定“3 道题”。
2）缺口 [待定]
演练是任务式分段训练还是完整一次专业交流？是否支持用户提前查看问题？
AI 何时追问、转题、澄清、中断、结束；是否根据答题质量动态调整难度？
角色模拟的“打断”“冷淡”“质疑”如何控制，防止不真实或侮辱性的表现？
演练失败（麦克风/网络/模型）是否可恢复、是否影响评价公平？
正式训练可用语音或文字吗？培训报告是否保存音频及保留多久？
3）下一步技术制作 [建议]
建 ScenarioPlan（目标、考点、难度、角色预设、时间预算）、SessionState（当前考点、对话轮次、已覆盖项、待追问项、结束原因）。
用有限状态机控制 prepare → ask → listen → evaluate-turn → follow-up/next → finish；LLM 只负责自然语言实现和候选追问，不能自行扩展未经审核的产品医学结论。
第一版语音采用 ASR→文本编排→LLM→TTS，保证能记录可审核文本；更自然的实时语音作为后续优化。
输入：获批训练计划+角色设定；输出：SessionTranscript、覆盖记录、结束原因；异常：断连允许恢复，不把无回答误评分为知识错误。
验收：跨角色风格专业要点保持一致；动态追问只在本计划授权范围内进行；结束能明确说明原因。

## 1.5 双维能力评估
目标：分开判断“怎么沟通”与“专业知识用得是否准确”，而非只有一个不可解释总分。
1）我们现在的设计 [已定]
沟通与应变五维：问题理解、回答结构、表达清晰、临场应变、情境适应。
专业知识运用：知识准确性、证据运用、适用边界、专业与合规要求。
员工可查看具体错误和复训建议；存在双系统分数及综合评价意图。
2）缺口 [待定]
每个维度的评分量表、证据阈值、权重、综合公式均未正式确定（先前权重仅为演示）。
按单轮、单考点还是整场评分？高难度模拟与低难度模拟如何比较？
严重知识/合规错误如何触发复核或不达标？
LLM 对不同语气、口音、转写错误产生的评分偏差如何排查？
两套评分何种情形允许由培训师申诉和人工改判？
3）下一步技术制作 [建议]
拆成 CommunicationRubricEngine 和 MedicalEvidenceRubricEngine，分别返回维度分、原文定位、参照考点、解释与 uncertain 标记；最后由规则引擎生成综合结论。
专业评分检索当次训练固定知识版本，不直接调用前沿日报未审信息；必要时引入硬性风险闸门。
建 RubricVersion 和专家标注黄金样本，复核一致性和跨角色稳定性；综合权重保留配置，未审批前标为试验评价。
输入：会话文本+考点+知识版本；输出：两套评分明细、风险提示、复训建议；异常：无证据或 ASR 严重错误→待复核而非硬给精确分。
验收：扣分能定位到具体回答与依据；专业性严重错误不被流畅表达抵消；跨风格比较时明确难度条件。

# 二、反馈进化（02）
业务主链：事后复盘 → 原话与观察拆解 → 预演/报告对照 → 真伪裁判审核 → 训练场景更新 + 员工弱项回流。
关键事实边界：复盘“医生说过什么”属于代表的报告；我们能核验的是专业知识依据，不能仅凭单人复盘证明一次现场交流的完整真相。

## 2.1 实战语音复盘
目标：在不增加过高填写负担的前提下，收集有情境、有不确定性标记的现场报告。
1）我们现在的设计 [已定]
代表真实交流后进行简短语音或文字复盘。
记录实际遇到的问题、自己的回答、未解决的问题和现场观察。
复盘数据可与之前的预测/模拟训练关联。
2）缺口 [待定]
是否要求必须关联某次 PredictionPlan？没有预演时的独立复盘是否允许？
多久后提交算“及时”；是否收集自报的“逐字/大意/不确定”？
什么内容严禁录入（患者可识别信息、未经授权的现场录音等），遇到不良反应信息如何引导走正式流程？
提交后是否允许撤回、修订、删除？哪些内容能被团队看到？
3）下一步技术制作 [建议]
表单采用 3 个主引导问题：对方问了什么、我怎么回答、我哪里不确定；附原话/概括/推断的来源选择。
建 DebriefRaw 保存原始转写、用户修订、发生时间、提交时间、可选预演 ID 和权限范围。
录音采集必须有授权和敏感内容提示；优先存可更正的文字，音频是否存储与期限由企业审批。
输入：语音/文字；输出：待确认复盘；异常：识别到敏感个人信息先拦截或要求脱敏；临床不良反应提示走法定/企业报告路径，不以本系统替代。
验收：用户可查看并修订转写；系统明确显示“回忆/原话/推测”标记；无预演 ID 时不制造预测命中率。

## 2.2 反馈结构化处理
目标：把自由叙述拆为可审查的“交流事件、专业问题、自我表现、主观推测”。
1）我们现在的设计 [已定]
AI 提取对方的专业问题、代表自述回答、个人观察和不确定性。
需要保留原文，并让用户确认提取结果。
不能将“医生不认可”之类主观推断自动写成专家事实。
2）缺口 [待定]
哪些字段缺失必须追问，哪些可以允许空值？
“我忘了原话”“我不确定理解对不对”如何影响下游权重？
同一段话包含研究事实与现场推断时，能否分别标记？
人工修订后是否触发重新解析及重算差异？
3）下一步技术制作 [建议]
使用结构化输出 Observation[]：kind=reported_question|self_answer|inference|unresolved、source_span、verbatim_level、reported_context、uncertainty_reasons[]、user_confirmed。
语言模型负责初步分类，规则校验源文本 span 的存在性；保留原始转写和修订历史。
将两个概念拆开：statement_is_medically_supported（医学论断是否有依据）与 event_occurrence_verified（事件发生是否有佐证），不可互相替代。
输入：确认过的复盘文本；输出：结构化观察；异常：信息不足→标记 needs_clarification，禁止 AI 补造细节。
验收：模糊评价不能被转化为真实专家的稳定偏好；所有抽取结果都能回溯原文。

## 2.3 预测与现实差异分析
目标：区分“学员没掌握”和“训练没覆盖”，但仅基于可见的预演记录和用户报告作候选判断。
1）我们现在的设计 [已定]
将前沿预测的训练考点与真实交流后报告的问题做对照。
识别已覆盖但未掌握、未覆盖的新专业问题，以及不清晰的记录。
输出后续训练和共享案例的改进方向。
2）缺口 [待定]
不同表述但同一知识考点时如何判断覆盖？什么算“部分覆盖”？
如果只讲过相关知识却没有演练过该问法，算不算训练覆盖？
多个训练考点映射到同一现场问题时如何记录？
复盘仅为单人回忆，是否可以参与训练质量的统计，怎样标注样本质量？
没有现场验证证据时，命名为“预测准确率”是否会造成过度宣称？
3）下一步技术制作 [建议]
建 SkillTaxonomy 与 CoverageMap：按能力点、医学证据主题、提问意图三级比对；LLM 候选匹配 + 结构化规则 + 边界样本人工复核。
差异结果显式分类 covered_mastered、covered_not_mastered、not_covered、partial、unknown，并记录 match_evidence 与 observation_quality。
对外报告使用“复盘报告的题目覆盖情况”，不要直接声称预测了真实医生的言行。
输入：PredictionPlan、AssessmentReport、Observation[]；输出：GapCandidate[]；异常：无先前预演→仅生成“可补充训练主题”，不计算命中率。
验收：不同专业能力点不能只因措辞相近而合并；对照结论标注“基于员工报告”。

## 2.4 真伪裁判所（共享能力）
目标：把“能提议更新”与“有权成为正式训练依据”严格分离。
1）我们现在的设计 [已定]
对文献和学术主张检查来源、时效、冲突与证据边界。
对员工现场报告保留主观性和不确定性；对正式训练案例执行审核。
日报、预测、反馈共用这一质量控制能力。
2）缺口 [待定]
医学事务、培训师、管理员对知识/题目/沟通风格分别拥有哪些审批权？
什么样的原始资料可被引用，全文使用/二次传播有哪些授权限制？
争议、撤稿、更正、资料过期如何影响现有题目和历史分数？
人工审核失败时是退回修改、隔离还是直接驳回？需要多级审核吗？
3）下一步技术制作 [建议]
建统一 ReviewCase，审核对象分 SOURCE、MEDICAL_CLAIM、QUESTION、SCENARIO、SCORE_APPEAL、FIELD_OBSERVATION；不同对象使用不同规则。
状态机 draft → auto_checked → pending_human → approved/rejected/needs_revision → published/retired；任何 pending 项不得进入正式知识与评分。
记录 reviewer、证据链、政策版本、结果、时间、理由，支持异常撤稿时的影响查询及回滚。
输入：候选内容+来源+变更原因；输出：签审决定+审计轨迹；异常：存在无法核实的重要医学主张→拒绝发布或挂起。
验收：未审核日报/现场推测无法污染正式标准答案；审核结果与发布动作有完整日志。

## 2.5 训练进化与个人强化
目标：实现两个不同层级的学习：个人能力补弱与共享训练内容版本升级。
1）我们现在的设计 [已定]
员工账号下保存长期易错知识点及沟通短板，安排专项复训。
经过真伪裁判的新增训练问题进入共享题库/场景库。
训练库与知识库定期更新，形成持续迭代。
2）缺口 [待定]
多次错误、长期改善和间隔复训按什么标准触发？
新增案例影响哪些科室、哪些员工、哪些旧场景版本？
新场景发布后，如何确认它比旧场景更有效？
历史员工分数是否沿用原评分版本，或需要重算？
企业是否允许用个人表现进行跨员工排名，数据如何限制用途？
3）下一步技术制作 [建议]
个人循环：AssessmentItem → EmployeeSkillState（skill、最近表现、错误类型、复测状态）→ RemedialAssignment；训练结果保持和角色难度、题目版本绑定。
共享循环：GapCandidate → 经审核的 Question/ScenarioDraft → 回归测试 → ScenarioVersion 发布；原版本保持可回放，重大问题支持回滚。
采用规则驱动的审核版内容更新，而不是自行修改模型权重；共享层与个人训练层数据隔离。
输入：经审差异候选+员工评估；输出：复训任务/版本更新；异常：评估不可靠→人工复核，不写入长期弱项。
验收：同一员工能看到错误改进轨迹；被拒绝的候选案例不会进入任何正式训练；可比较 V1/V2 考点差异。

# 三、每日前沿日报（03）
业务主链：增量采集 → 来源检查与筛选 → 个性化摘要 → 学术交流话题 → 周度审核与知识沉淀。
重要边界：日报支持了解学术前沿与寻找合适话题；不要求用户每次开始模拟时重新追踪最新新闻。

## 3.1 前沿信息采集
目标：持续从指定可信来源发现与企业内部培训相关的医学研究更新。
1）我们现在的设计 [已定]
日报按员工科室/疾病/产品领域关注最新研究、论文和学术动态。
后台按日采集，知识库有定期审核更新机制。
2）缺口 [待定]
首批纳入哪些学科、产品、疾病领域和语言？哪些信息源在企业授权清单上？
“今天更新”指发表日期、数据库收录日期还是本系统发现日期？
论文、预印本、临床试验登记/结果、指南与大会摘要是否属于日报范围？
内容抓取失败时，是否展示上一期、空态还是重试提示？
3）下一步技术制作 [建议]
SourceConnector 对接 PubMed E-utilities、Crossref 元数据和授权的其他来源；保留 published_at、indexed_at、collected_at、updated_at 分别表示不同时间。
用调度作业维护 last_successful_cursor，采用增量查询、重试、配额控制、幂等入库与错误告警。
优先抓取允许使用的元数据、摘要和链接；未获许可不得批量保存受限全文。
输入：学术订阅主题+来源清单；输出：SourceDocument 新候选；异常：来源故障→保留上次游标且显示信息新鲜度。
验收：同一 DOI/PMID 多次采集不造成重复；日报时间标签准确区分发表与发现。

## 3.2 信息筛选与可信核验
目标：判断采集内容是否真实、相关、可用，不能简单以“新”代替“可信”。
1）我们现在的设计 [已定]
对文献去重、验证来源、核查发表时间、区分新信息与正式训练知识。
真伪裁判所对争议内容进行统一治理。
2）缺口 [待定]
预印本、会议摘要、正式同行评审论文、指南和药品官方资料分别如何标记？
纠错/撤稿/更正、重复研究报告和夸大结论怎么处理？
只有摘要没有全文时，AI 可以写到什么程度？
与当前企业合规使用范围冲突时，是保留内部参考还是屏蔽？
3）下一步技术制作 [建议]
建 SourceDocument、EvidenceClaim 和 SourceStatus；按 DOI/PMID/标题聚合近似重复，保留源记录不静默覆盖。
内容状态至少区分 collected、metadata_checked、summarized_for_awareness、medical_reviewed、approved_for_training、withdrawn。
对单条摘要生成重要论点时记录证据定位；有撤稿/更正信号触发影响分析，不能依赖单次抓取永不复查。
输入：候选来源；输出：带证据状态的可用候选；异常：无法确认来源→隔离或只显示原始元数据且标“待核实”。
验收：未经审查的研究不进入正式评分答案；撤稿标记可以追踪到所有引用该资料的内容。

## 3.3 个性化日报生成
目标：把信息整理成员工每天能快速阅读、知道为何相关的专业摘要。
1）我们现在的设计 [已定]
围绕员工关注学科、疾病、产品领域生成定制日报。
提供主要发现、局限、来源和审核状态。
2）缺口 [待定]
个性化依据来自账号岗位、员工订阅还是历史训练表现？如何允许调整？
每天展示篇数、排序、去重周期及阅读时长目标未确定。
同一研究不同来源重复发布，日报是否需要增量提示？
没有新内容时如何避免模型编造“今日热点”？
3）下一步技术制作 [建议]
DigestSubscription 管理领域标签、来源偏好；DigestIssue 固化日期、筛选集合、模型版本和生成时间。
先做主题匹配与质量排序，再做基于来源片段的摘要；每条卡显示题目、发布日期/收录日、发现理由、证据状态和原始链接。
日报可展示“仅供学习/待医学审核”的研究，但其可用于正式交流的权限单独控制。
输入：订阅+核验候选；输出：当日日报；异常：无新增→真实空态/回顾旧内容并明确标识，不生成虚假更新。
验收：每条日报有来源与日期；切换订阅领域影响推荐；不可将旧文伪装成当天发表。

## 3.4 学术交流切入点
目标：从日报中抽取能够引发专业讨论的启发，而非输出未经核验的产品宣称话术。
1）我们现在的设计 [已定]
每日资讯需要补充“可以开启专业交流的信息”。
内容来源于医学前沿，服务于学习和专业话题发现，不替代拜访前问题预测。
2）缺口 [待定]
系统输出“可讨论话题”还是“可直接对医生使用的推荐开场句”？两者风险不同。
未经审核的研究能否生成仅供内部学习的启发型问题？
如何识别超出批准用途、过度外推或暗含疗效比较的开场建议？
用户如何将有价值的话题收藏/送审/用于后续准备？
3）下一步技术制作 [建议]
将输出分为 learning_prompt（内部启发，待审）与 approved_talking_point（专业审批后可用）两种权限对象。
基于证据卡生成中立的研究讨论问题，如“这项研究的入组条件对结果解释有哪些影响？”；不生成未经审核的临床结论或推销措辞。
输入：日报条目+状态；输出：一个或多个有明确状态的交流切入点；异常：新资料证据不足→只提供背景阅读，不给正式话术。
验收：待审内容有显著使用限制；正式可用切入点必须有审批 ID 和来源。

## 3.5 前沿知识沉淀
目标：把每天新发现的高价值信息，经周期审核沉淀为稳定可追踪的训练知识版本。
1）我们现在的设计 [已定]
日报每天采集和展示新信息；后台按周检查、审核知识候选，按需更新知识库。
新研究不应自动改变旧模拟训练中的专业标准答案。
2）缺口 [待定]
知识卡与证据主张的最小粒度是什么？如何关联多个研究相互支持或冲突？
按周审核是固定发布、固定复查还是按变更触发发布？
研究新版本与现有题目/评分/日报之间的影响范围如何检查？
过时内容是归档、标记禁止使用，还是允许历史回放？
3）下一步技术制作 [建议]
KnowledgeCandidate → EvidenceClaim → ReviewCase → KnowledgePackVersion；周度任务负责产生候选审查包，审批通过才发布新知识版本。
KnowledgePackVersion 用不可变快照 version_id 挂接每一次正式训练，保证回放可复现；新证据通过影响图定位旧题目。
输入：日报候选、专家审查结论；输出：新知识包/影响清单；异常：无通过审核的更新→本周不发布新版本。
验收：日报与训练库可不同步但状态透明；知识版本变更不会静默修改历史训练评分。

# 四、跨模块闭环与共享架构

## 4.1 三条独立但相通的数据流
A. 前沿预测（任务级、在线）
VisitContext → ExpertProfile(已核验线索) → ApprovedKnowledgeSnapshot
  → QuestionCandidate → PredictionPlan → SimulationSession
  → DualAssessment → EmployeeSkillState

B. 反馈进化（回忆驱动、异步审核）
DebriefRaw → Observation(原话/概述/推测) → GapCandidate
  → ReviewCase → ScenarioDraft → RegressionTests → ScenarioVersion
                                     └→ EmployeeRemediation

C. 每日前沿日报（日期驱动、后台）
SourceConnector → SourceDocument → SourceCheck → DigestIssue
  → LearningPrompt → WeeklyReview → KnowledgePackVersion

共享控制：Identity/RBAC｜Evidence/Provenance｜TruthReview｜Audit｜Versioning｜Evals
交叉规则：
日报新信息在 approved_for_training 前不能进入正式答案和专业评分；可以按权限用于“阅读/了解”栏目。
人工复盘的现场发生情况不等于经客观验证的医生言行，不被自动写入 ExpertProfile 的确定性字段。
一次训练固定 knowledge_pack_version、rubric_version、scenario_version 和 role_preset_snapshot。
“个性化复训”根据员工训练表现产生；“共享题库变化”必须审核发布。两条进化路径不要合并。

## 4.3 核心状态机（建议）
候选知识：discovered → source_checked → awaiting_medical_review → approved_for_training / rejected / needs_revision → published → retired。
反馈案例：captured → transcribed → user_confirmed → gap_analyzed → review_pending → approved / rejected → scenario_proposed → tested → published。
演练会话：created → ready → active → paused/recoverable → completed / cancelled / failed → assessed / assessment_pending_review。
规则：状态转移写在程序与数据库事务中，不能靠 LLM 自由写状态；审核人、被审核对象、知识快照和发布版本有明确可查询的关联。

## 4.5 前沿工程架构选择
一期建议：沿用现有 Next.js + TypeScript 主体，先作为一个模块化单体；原有会话、场景和评分功能可作为待审计基础，不假定已通过生产验证。
数据库：小规模演示可继续 SQLite；多人内部试点建议 PostgreSQL。向量检索不是一开始必须：先有可信的来源索引和全文/关键词检索，数据量变大后再加 pgvector + 混合检索和重排序。
AI 结构化能力：Zod/JSON Schema + 模型结构化输出处理问题、观察和评分；结构校验≠医学事实核验。
上下文工程：每次推理只载入当前允许使用的知识快照、能力目标、角色设定和必要历史；将证据 ID 明确传给模型，避免无限堆砌文献。
工作流工程：先用服务端状态机与后台作业；若出现跨天审批、暂停恢复和多阶段复杂工作流，再采用 LangGraph 等持久执行框架。
语音工程：优先独立 ASR→文本编排→TTS，便于质量回溯；低延迟实时语音作为后续增强。
追踪与评估：记录模型版本、提示词版本、检索结果、引用链、模型输出、审核结论；数据集回归测试比“多 Agent 自我辩论”优先。
安全与治理：最小权限、企业身份认证、敏感信息检测、数据留存策略、审核人独立权限、关键高风险医学结论人工把关。
不建议一期采用：多模型相互无限辩论、自动训练大模型权重、不可解释的“专家提问概率”、自动把现场印象固化为某位真实医生的性格特征。

# 五、模块依赖、开发顺序与交付里程碑

## 5.1 技术依赖（不是页面顺序）
共同地基：身份权限、知识状态、来源证据、SkillTaxonomy、审核与审计、版本快照、评估样本。
预测链 P0：1.1 场景配置 → 1.3 问题选择 → 1.4 模拟交互 → 1.5 双评分；1.2 专家公开线索逐步接入（先人工录入已核验样本也能验收闭环）。
反馈链 P0：2.1 复盘 → 2.2 结构化 → 2.3 差异 → 2.4 审核 → 2.5 V2 发布和个人复训。
日报链 P0/P1：3.1 采集 → 3.2 筛选 → 3.3 日报 → 3.4 切入点 → 3.5 周度知识候选；一期至少保证日报可读、有来源、可正确标注审核状态。

## 5.3 关键验收场景（一期至少覆盖）

[TABLE 4]
测试 ID | 情形 | 必须得到的结果
AT01 | 只选科室，未填专家 | 可按通用科室训练降级，绝不捏造专家履历
AT02 | 目标专家与另一个作者同名 | 展示待核实，不直接绑定论文
AT03 | 预测问题数量需要因任务变化 | 题目数量可变、每题有选择理由，不能固定死 3 道
AT04 | 新日报摘要尚未审核 | 可以内部阅读（若政策允许），不可作为正式知识评分依据
AT05 | 同一审核知识包切换医生情绪 | 医学答案及合规边界不变，语言风格可变
AT06 | 代表语音报告“医生好像不认可” | 标注主观推测；不把它固化为医生人格事实
AT07 | 员工自述医生问题的原话记不清 | 保留“大意/不确定”；不生成虚假逐字对话
AT08 | 上次练过研究终点，这次报告亚组证据 | 能识别不同能力点并提出未覆盖候选，而非仅文字相似即命中
AT09 | 无原预演计划却提交复盘 | 不计算“预测命中率”；可形成训练主题候选
AT10 | 医学核验失败或审核拒绝 | 新内容无法发布，旧场景保持不变
AT11 | 场景 V2 发布 | 可以显示“新增何考点、为何新增、谁审核”；支持恢复 V1
AT12 | 专业内容错误但表述流畅 | 风险标记/不达标规则优先，不被沟通高分简单抵消
AT13 | 当天未采集到新研究 | 日报显示真实空态或历史回顾标签，不编造“今日最新”
AT14 | 文献撤稿或更正 | 找到受影响的知识卡、题目、日报条目并触发复核
AT15 | 同一员工连续训练同一能力 | 记录独立于总分的能力轨迹；历史结果带版本和难度
AT16 | ASR 失误导致误判 | 用户可改正转写，重算评分或转人工复核

## 5.4 对应核心质量指标（建议起步）
证据层：正式题目的引用覆盖率、来源可访问率、未经审核资料进入正式评分的次数（目标为零）。
预测层：问题的专业审核可用率、建议理由可解释率、能力点覆盖率；不虚构“某专家提问概率”。
反馈层：结构化提取与人工标注一致率、误将推测当事实的比率、差异判定人工复核一致率。
训练层：专业/沟通评价与培训师一致率、跨情境复测表现、延迟复测表现。
进化层：审核通过的新候选进入下一训练版本的完整率、可追溯率、因更新导致的回归缺陷数。
日报层：时效标签准确率、来源链接覆盖率、重复条目率、用户相关性反馈。
所有数值阈值需在先导标注集建立后确定；当前不能捏造验收成功率。
