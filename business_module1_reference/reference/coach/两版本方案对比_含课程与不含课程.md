# MedRep Coach 两版本方案对比 —— 含课程 / 不含课程

> 依据：MedRep Coach V1.3 开发文档 + 本项目已产出（42 门课 / 222 个能力点 / 语料资产库 / 临床知识库）
> 目的：把 V1.3 的 **D01（一期科室、产品/研究主题和批准资料范围）** 落到两个可比较的方案上，供产品方选型。

---

## 0. 一句话结论

| | 版本 A：含课程 | 版本 B：不含课程 |
|---|---|---|
| 一期最快可交付 | **T+8 周**（课程已就位 42 门，签审后可上） | T+14 周（需先建复盘采集与一线陪跑） |
| 一期核心资产 | 42 门课 + 48 条场景种子 | 场景库 + 复盘数据管道 |
| 一期阻塞 | **医学审核产能**（42 门需逐门签审）| **一线药代参与度**（复盘是人工密集的）|
| 长期价值来源 | 内容资产的复用与扩展 | 真实反馈驱动的持续进化 |
| 风险 | 课程会过期（语料多为 2000–2015）| 无内容则冷启动期几乎无训练素材 |
| 人日 | **+49**（共 327）| **+42**（共 320）|

**建议：选 A 起步，但按 B 的架构预留复盘入口。** 理由见 §5。

---

## 1. 先说清"加课程"到底加了什么

这不是给界面加个课程列表。V1.3 的知识分层决定了它的真实含义：

```
候选层（现在 42 门课都在这里，pending_medical_review）
   ↓ ReviewCase 签审
已审核训练层（只有这层能进正式评分）
```

**所以"加课程"这个决定的实际内容是：把课程从候选层推到已审核训练层。** 工作量不是"再写几门课"，而是：

| 工作项 | 说明 | 人日 |
|---|---|---|
| 42 门课逐门医学签审 | 每门需确认：适用范围表述、核实路径说法、误区纠正是否可作为标准答案 | 21 |
| 84 道检验题补 rubric 与分值 | 现有 `grading_mode` 全是人评；机器评分需补标准答案、反例、分值 | 14 |
| 课程 → KnowledgeCandidate 接入 | 课程条目转成可签审候选，走 ReviewCase 流程 | 8 |
| 课程学习路径编排 | 按 SkillTaxonomy 组织课程序列与难度阶梯 | 6 |
| **合计** | | **49** |

**已完成的 42 门课（disease_foundation 维度）在这里直接产生价值**，不是白做。

## 2. 两版的架构差异

### 2.1 训练内容从哪来

| | 版本 A（含课程）| 版本 B（不含课程）|
|---|---|---|
| 训练素材主来源 | 课程（已审核层）+ 48 条场景种子 | 场景库 + **真实复盘产生的缺口候选** |
| 训练内容的产生者 | 培训/内容团队（前置投入）| 一线药代复盘（持续投入）|
| 首次可用时间 | 快（课程在库）| 慢（要等复盘积累）|
| 内容新鲜度 | 靠周更审计（V1.3 §3.5）| 天然新鲜（来自真实拜访）|
| 覆盖广度 | 受课程开发进度限制 | 受一线参与面限制 |

### 2.2 两条数据流的关系（V1.3 §4.1）

```
A 版：知识包（课程签审）→ 候选考点 → 演练 → 双评分 → 员工弱项
                                    ↓
                              复盘（可选，二期接）

B 版：场景库 + 复盘 → GapCandidate → 审核 → 场景 V2 → 演练 → 双评分
                            ↑____________________|
                            （闭环更快，但缺现成素材）
```

**关键差异**：A 版的"进化"回路在二期才接通，一期是单向的（课程 → 训练）；B 版从第一天就有回路，但回路需要真实数据才能转起来。

## 4. 关键差异：成本结构，不是工作量

| 维度 | 版本 A | 版本 B |
|---|---|---|
| **前置投入** | 高：一次性做 42 门课签审 + rubric | 低：不需要课程，但要建采集流程 |
| **持续投入** | 低：课程可复用，边际成本递减 | 高：每轮复盘都要人工参与 + 审核 |
| **瓶颈** | **医学审核产能**（1–2 人逐门过 42 门）| **一线药代参与度**（复盘是人工密集的）|
| **可自动化程度** | 高：签审一次，内容长期复用 | 低：结构化抽取可自动化，但复盘采集不可 |
| **规模效应** | 课程越多，单位成本越低 | 复盘越多，数据越厚，但人力线性增长 |
| **知识过期风险** | 高：语料多为 2000–2015，需周更审计 | 低：来自真实拜访 |
| **冷启动期** | **无**：课程已在库 | **有**：需先积累复盘样本 |

**一句话**：A 版是"前期重、后期轻"，B 版是"前期轻、持续重"。

---

## 5. 为什么建议 A 起步

三个理由：

**① 冷启动期是致命窗口。** B 版没有复盘样本时，AI 医生只能靠通用场景规则生成问题——这恰恰是 V1.3 AT05/AT12 要防的场景（风格变了医学答案也变、专业错误被表达流畅掩盖）。A 版用已审核课程起步，直接绕开这个窗口。

**② 课程资产不会白做。** 42 门课 + 222 个能力点 + 映射表，在 A 版直接进已审核层；即使将来走 B 版，课程的 skill_id 结构照样能当 CoverageMap 的能力点字典。**课程不是"要不要"的二选一，是"先不先做"的排序问题。**

**③ A 版可以平滑演进到 B 版。** 两版共用 SkillTaxonomy、ReviewCase、KnowledgePackVersion。二期接复盘流时，课程不用重做，只是多一个 GapCandidate 来源。

**但 A 版必须带一个约束**：**课程签审不能省。** 现在 42 门课全部 `pending_medical_review`，按 V1.3 §0.2 不进正式评分。如果跳过签审直接拿课程当训练依据，就是在违反 V1.3 最核心的约束——这比做 B 版更危险。

## 6. 两版的 AT 验收差异

V1.3 的 16 个 AT 里，**三处的通过方式不同**：

| AT | 版本 A 的通过方式 | 版本 B 的通过方式 |
|---|---|---|
| **AT04** 新日报摘要未审核 → 不可作正式知识依据 | 同（两版都有日报最小集）| 同 |
| **AT08** 上次练过研究终点，这次报告亚组证据 → 识别不同能力点 | 靠**课程与复盘的能力点 ID 对齐**（课程已建 skill_id，回填到复盘抽取）| 靠 **CoverageMap 三级比对**（能力点/证据主题/提问意图）|
| **AT09** 无预演计划却提交复盘 → 不计算命中率 | 同样适用；**A 版一期没有复盘流时该条不激活** | 该条是 B 版的核心，必须实现 |

**结论**：A 版一期可豁免 AT08/AT09 的复盘侧验证，二期必须补齐。

## 7. 两版的一期范围建议（D01 落地）

### 版本 A 的一期范围（建议）

| 项 | 建议 |
|---|---|
| 治疗领域 | **实体瘤与肿瘤免疫**（16 个疾病，课程最密集）|
| 疾病 | 建议先取该领域内 6–8 个高频病种（如 NSCLC / 乳腺癌 / 肝癌 / 胃癌 / 结直肠癌 / 卵巢癌）|
| 产品 | 建议 2–3 个已商业化产品 + 1–2 个在研资产（覆盖"已获批"与"在研"两类边界场景）|
| 课程维度 | 先做 `disease_foundation`（42 门已就位）+ `treatment_landscape`（42 门骨架已备）|
| 语料素材 | 语料中的 48 条场景种子全部可用（按疾病分布取用）|
| 试点规模 | 20–30 名药代 × 6 周（比旧版 4 周长，因为要配合医学审核与课程熟悉）|

### 版本 B 的一期范围（建议）

| 项 | 建议 |
|---|---|
| 治疗领域 | 同样先做肿瘤，但**范围可以更窄**（B 版靠现场数据，不需要预置广覆盖）|
| 疾病 | 3–5 个病种即可，靠真实拜访自然覆盖 |
| 产品 | 同上 |
| 场景种子 | 48 条作为冷启动底座，之后由复盘补充 |
| 试点规模 | 20 名药代 × **12 周**（必须跑够复盘轮次才有数据）|

| # | 决策 | 建议 | 影响 |
|---|---|---|---|
| D01a | **选 A 还是 B** | **选 A**（冷启动窗口 + 课程复用性）| 决定一期范围与医学审核排期 |
| D01b | 一期治疗领域 | 实体瘤与肿瘤免疫 | 决定签审哪批课程 |
| D01c | 一期疾病数 | 6–8 个（不要 42 门全签）| 直接决定 21 人日审核的排期 |
| D01d | 一期产品数 | 2–3 商业化 + 1–2 在研 | 决定"已获批/在研"边界场景能否覆盖 |
| D04a | 题量策略（两版相同）| 按时长预算 + 能力点覆盖数 + 用户选择，1–8 题可配 | 需产品+培训确认上下限 |
| D08a | 两套评分量表与严重错误闸门（两版相同）| 先用 V1.3 命名 + 我们的扣分信号锚点，医学事务补分值 | D3 冻结的前置 |
| **新增** D01e | **课程签审是否阻塞上线** | **阻塞**。按 V1.3 §0.2，未签审课程不得进正式评分 | 若不阻塞，则 A 版违反 V1.3 核心约束 |

## 9. 若选 A，一期要立刻做的三件事

1. **确认一期疾病清单**（D01b/c）→ 只对清单内的课程启动签审，其余延后。21 人日是按 42 门估的，8 门只要 4 人日。
2. **排医学审核档期**（D01e）→ 审核是硬瓶颈，必须先排进去，不能等开发完了才找人。
3. **补 84 道检验题的 rubric**（S1-A2）→ 这是机器评分的前提。现有课程里 34 道边界判断题已标了"含核实路径"这类判别依据，可作为 rubric 起草的起点。
