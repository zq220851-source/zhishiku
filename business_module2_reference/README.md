## 模型设置

复制 `.env.example` 为 `.env.local`，在服务端填写 `MODULE2_MODEL_BASE_URL`、`MODULE2_MODEL_NAME`、`MODULE2_MODEL_API_KEY`，明确允许测试资料外发后设置 `MODULE2_MODEL_DATA_AUTHORIZED=true`，重启本应用。Base URL 是兼容 Chat Completions 的 API 前缀（例如网关提供的 `/v1`），应用追加 `/chat/completions`；这只定义传输适配方式，不预选供应商或模型。不兼容该传输协议的服务需单独适配。

未设置时可以创建任务、保存和修订原文；分析明确失败并保留原文，不返回关键词或固定业务结果。密钥不返回浏览器、不记录在事件里。接口路径 `/api/module2`。

当前用户选定网关 `https://api.openai-next.com/v1` 与模型 `deepseek-v4-pro`，密钥单独存于服务端；该连接已用虚构主用例实测，见 `docs/API接入验证记录.md`。`MODULE2_MODEL_THINKING` 可留空不发送，当前 DeepSeek 结构化抽取配置为 `disabled`。传输与一次结构纠正共享 90 秒预算，失败不返回本地关键词结果。

## 内部风险接收箱

保存含显式风险线索的复盘时，在同一事务内保存原文、隔离和分流。页面切换到对应测试职责后可查看原文及历史版本提示，依次确认接收、开始处理、填写结果后结束处理。职责切换保持当前测试者身份，使用服务端签名会话，不能通过业务请求伪造其他员工身份或接收职责。

每个原文版本/接收职责只投递一次；重试幂等，过期事项版本阻止覆盖。员工修订原文不自动撤销旧事项；内部处理结束不解除隔离，不发布医学内容。路由与各次处理记录留痕，审计事件不复制风险原文。
