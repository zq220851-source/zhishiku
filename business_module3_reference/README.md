# MedRep Daily · 信达生物医药代表培训日报原型

一份日报包含两部分：所有代表共读的中国医药行业动态，以及按负责产品筛选的产品与在研学习。产品目录以[信达生物官网管线](https://www.innoventbio.com/#/pline)为准；仅已上市产品可作为负责产品，在研项目只用于学习并标明“尚未获批”。本项目是独立原型，没有接入尚在开发中的 MedRep Coach，也没有录入任何员工的实际分配关系。

## 黑客松演示人物

“我的信息”页只展示一位**虚构人物林知安**：高级医药代表、IO BU、姑苏区与虎丘区。页面设置 2 条已上市负责产品（达伯舒®、达伯欣®）和 1 条在研学习管线（IBI-363，标明尚未获批），以及 7 家医院、22 位医生、14 位关键人。岗位、辖区与数量参照用户提供的示例截图；**人物、医生、关键人、医院覆盖关系和个人产品分配均为虚构**，不代表信达生物的真实员工或商业布局。截图未给出第三条个人管线的名称，因此 IBI-363 是为演示而作的学习方向设定，不是事实推断。

7 家医院的**机构名称**取自[苏州市人社局公开名录](https://hrss.suzhou.gov.cn/jsszhrss/gsbxsxcx/202605/23b01681549845fb94d81c9159cebeb5.shtml)：苏州大学附属第一医院、苏州市立医院、苏州平江医院、苏州金阊医院、苏州科技城医院、苏州高新区人民医院和苏州明基医院。公开名录只用于核对医院名称，不能证明林知安或这些虚构医生与医院存在任何真实关系。

首页把“我的信息”融入日报入口。行业动态仍为全员共读；产品与在研学习由服务端读取演示档案中的已上市产品 ID 进行筛选，每条学习内容标明推荐理由。医院按辖区展示，点击后才展开医生名单，避免把 22 人铺成难读的表格。飞书只提供文本预览，没有真实接收人，也不会发送。

## 本地运行

需要 Node.js 22 及以上，无需安装第三方 npm 包。在项目目录执行：

```sh
npm run dev
```

打开 `http://127.0.0.1:8787`。进入“我的信息”可看演示人物与负责方向，再点“查看我的日报”体验个性化日报。`PORT=8788 npm run dev` 可换端口。当前演示期的 2 篇 IO 方向英文文献已缓存标题与完整来源摘要的中文译文；新文章的自动翻译仍需配置服务器端模型。

## 主任学术画像

左侧“主任学术画像”输入**医院全称＋姓名**，无需手动查论文。服务端把中文姓名转为拼音检索别名，用 [OpenAlex](https://help.openalex.org/api/) 匹配机构和候选作者，按同一条论文署名中的作者 ID 与机构 ID 筛选近期论文。带 PubMed 编号的记录再向 [Europe PMC 医学文献索引](https://dev.europepmc.org/RestfulWebService)核对。页面保留原题、作者署名、医院署名、日期和直达来源链接；英文标题自动机器翻译成中文，可展开原题。默认公开案例是苏州大学附属第一医院陶敏；论文和 2026 年 [中国临床肿瘤学会官方日程](https://meeting.csco.org.cn/home/program/39)实时查询，2025 年官方会后简讯及 2021 年讲座报道作为注明日期的已核对案例记录。

可选在**服务端运行环境**设置 `OPENALEX_API_KEY`。系统只把它放在发往 OpenAlex 的 `Authorization: Bearer` 请求头中，不会返回给浏览器或写入源码。无密钥时仍可进行基本检索；有密钥可提高 [OpenAlex 官方说明的检索额度](https://help.openalex.org/api/authentication/)。这个密钥不提供会议或演讲网页检索能力。

本地开发时可把密钥写入项目根目录的 `.env.local`，`npm run dev` 会自动读取；该文件已被 Git 忽略，权限应限制为仅当前用户可读。打包或分享项目目录时不要包含此文件。

同事解压分享包后，可直接运行 `npm run dev`；也可在 macOS 上双击 `启动日报.command`。如需提高 OpenAlex 的论文检索额度，可双击 `启动学术画像_输入OpenAlex密钥.command`，在终端临时输入**自己的**密钥，或复制 `.env.example` 为 `.env.local` 后在服务端填写。分享包不包含任何本机密钥或 `.env.local`，因此无密钥时仍可查看日报并使用公开接口的基本学术检索。

**同名作者不是身份认证。** 多个同名作者档案会分别列明；即使论文的同一署名行出现目标医院，也仍可能存在同名同院，使用前要核对医院主页、ORCID、科室等原始信息。检索结果只是公开索引中的前 12 条近期记录，不是完整履历，也不做“学术能力”评分。

会议与演讲先自动读取 2026 年中国临床肿瘤学会官方日程，仅收录**同一日程行同时出现姓名、医院和活动角色**的记录；官方日程只能证明被列入议程，不能证明实际到场。陶敏案例另展示 [2025 年官方会后简讯](https://www.csco.org.cn/cn/ncontent.aspx?oid=9192)和 [2021 年历史讲座报道](https://www-search.liangyihui.net/doc/73959)，明确区分“专家讨论”“开场致辞”和“讲座”。更广泛的网页检索可接 [Brave Search API](https://api-dashboard.search.brave.com/api-reference/web/search/get)，需在服务端配置 `BRAVE_SEARCH_API_KEY`；未配置时不声称已经完成全网检索。搜索摘要结果仍标为**待核对线索**。付费医学数据库、封闭会议资料、视频语音转录和全网完整覆盖尚未接入。此功能使用公开职业学术信息，不抓私人联系方式。

“代表工作中心 × 公开学术证据”根据虚构代表负责的达伯舒®与达伯欣®，分开展示结肠癌／MSI-H/dMMR、肿瘤免疫／PD-1、CTLA-4／双免联合三个关注点。点击条形可查看命中的原始记录。条形只表示本次采集标题与摘要的关键词命中数量，不是医生能力、临床偏好、产品使用或销售价值评分；陶敏是公开学术案例，不是演示人物的真实覆盖医生。两药联合的获批范围以[信达生物港交所公告](https://www1.hkexnews.hk/listedco/listconews/sehk/2025/1229/2025122900105_c.pdf)为依据。

拼音字表由 [pinyin-pro](https://github.com/zh-lx/pinyin-pro) 3.29.5 生成，运行时无需安装依赖；少数多音字可能需要人工确认。其 MIT 许可见 `THIRD_PARTY_NOTICES.md`。

## 信源与筛选

- 全员行业动态：国家医保局政策法规、通知公告、医保动态，以及国家药监局药品评价中心通知索引。当前只抓各栏目列表页近 30 天的候选，药监索引收录日期不冒充原文发布日期。
- 产品目录：每天读取[信达生物官网产品管线 API](https://www.innoventbio.com/api/products/new/index)，不可用时退回 2026-10-31 核验快照。当前快照有 47 条管线记录，其中 20 条在官网标为已上市。官网介绍页的 18 条数字注明“截至 2026 年 3 月”，与当前管线快照日期不同。
- 产品与在研学习：[信达生物公司新闻稿](https://www.innoventbio.com/#/news)和 Europe PMC 的 PubMed 文献索引。公司新闻稿是企业披露，不替代监管原文；“上市申请获受理”与“已获批”分开标注。在研项目通过相同治疗领域和靶点关联已上市产品；不因同属“肿瘤”就推给所有肿瘤产品代表。
- 国际文献按已核验的英文通用名检索，匹配标题或摘要；没有英文名映射的产品不会被英文关键词臆测匹配。国际研究不等于中国获批、医保准入或指南推荐。

每条内容保留来源链接、日期、来源类型、推荐理由及阅读边界。内容用于内部学习，未经医学审核。没有足够内容时显示空状态，不拿历史样例补足今日日报。药监主站批准数据库、CDE、各省招采、商业数据库及国内指南库仍待接入。

## 每天 08:00 的云端更新

Worker 已实现 `scheduled()` 定时采集入口和 R2 持久快照，使用北京时间 08:00 对应的 UTC cron 表达式 `0 0 * * *`。有 `BUCKET` R2 绑定时，定时任务写入 `daily/YYYY-MM-DD.json` 和 `daily/latest.json`；网站先读已保存日报，来源全部失败时不覆盖上一期。`/health` 可查询持久化快照时间。

**当前云端定时尚未启用。** 本地运行仍是按需采集和 15 分钟内存缓存，关电脑后不会更新。要实现关电脑仍运行，需要将这个 Worker 部署到具备 R2 绑定和每日 cron 的云端环境，并完成一次云端采集与读回验证。`wrangler.example.toml` 给出 Cloudflare 原生部署配置模板；发布前需填入并创建自己的 R2 bucket。现有 Sites 项目仍未发布，不能把“计划 08:00”当成已生效的任务。

员工产品分配表到手后，可用真实授权的“员工 ID → 已上市产品 ID”映射替换虚构档案；在此之前不生成任何真实员工的个性化日报。

## 可选飞书投递

网页是默认阅读渠道。打开“我的信息 → 投递预览”，可预览按演示人物负责方向生成的飞书文本消息；预览接口不会发消息。飞书不是当前已连接渠道，也不假设信达生物使用飞书。消息保留全员行业动态和个人产品学习两个部分、原文链接及医学审核提示；有译文的英文标题会显示中文，无译文时显示待翻译状态。

如企业确认使用飞书，管理员需在其企业租户内创建自建应用、启用机器人并授予 `im:message:send_as_bot` 权限，完成应用可用范围与员工授权。服务端配置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，不得写入前端或仓库。员工产品分配文件只放在私有 R2 对象 `delivery/assignments.json`，格式如下；`product_ids` 只能填官网管线中的已上市产品 ID：

```json
[
  {"employee_id":"E001","feishu_open_id":"ou_REPLACE_WITH_REAL_OPEN_ID","product_ids":["1"],"active":true}
]
```

示例值仅说明字段，不能用于真实发送。`employee_id` 是内部稳定编号，`feishu_open_id` 必须从同一飞书企业应用取得。核验一名测试员工的产品分配和消息内容后，才将云端环境变量 `FEISHU_DELIVERY_ENABLED` 设为 `true`。届时北京时间每天 08:00 的云端采集成功后按人发送，并在 R2 记录每日发送结果以避免重复；发送失败可重试。若企业不用飞书，可保留网页日报并另接企业微信、钉钉或其他内部渠道，内容生成不依赖飞书。当前尚无真实员工分配文件、企业飞书应用和已部署的云端定时任务，所以没有自动推送。

飞书适配使用[企业自建应用访问凭证](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)与[发送消息接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1)。应用在企业租户内的可用范围及机器人权限需由企业管理员确认。

## 中文翻译

本地缓存含 6 篇历史宫颈癌文献、2 篇当前 IO 方向文献的**标题与完整来源摘要**译文，不是论文全文翻译。译文与来源标题和摘要的指纹绑定，来源内容变更后不复用旧译文。新文章若需自动翻译，在服务器端设置 `LLM_API_URL`、`LLM_MODEL`、`LLM_API_KEY`；密钥不得写入前端或仓库。服务器在组装日报时尝试翻译新英文文献。无模型或失败时，中文阅读显示“待翻译”提示，用户仍可切换英文原文；绝不把英文摘要伪装成中文。译文未经过医学审核。参见 `prompts/translate.md`。

## 验证与接口

```sh
npm run build
npm test
npm run validate
```

- `GET /api/config`：来源、已上市产品目录、时区与定时配置状态。
- `GET /api/digest?mode=live&products=1&length=standard`：实时双板块日报。`products` 只接受官网已上市产品 ID；空值只显示全员行业动态。
- `GET /api/digest?mode=live&profile=me`：单人虚构演示日报。服务端从演示档案决定已上市产品，忽略客户端传入的 `products`；这不是生产身份认证。
- `GET /api/translation?id=...`：本期文章的缓存或按需摘要翻译。
- `GET /api/delivery-preview?profile=me&length=standard`：只生成虚构人物的飞书文本预览，不发送；通用接口仍可用 `products=1` 预览筛选结果。
- `GET /api/scholar-profile?hospital=北京大学肿瘤医院&name=沈琳`：按医院和姓名生成可溯源的公开学术资料；`BRAVE_SEARCH_API_KEY` 控制网页会议线索检索。
- `GET /health`：服务与快照状态。

参考 [Follow Builders](https://github.com/zarazhangrui/follow-builders) 的集中采集、内容整理与投递分离思路；代码为独立实现，未引入原项目依赖。
