# 飞书后台与账号接入

此阶段实现的是 **飞书 H5 的临时 code → 后端核验 → 本地平台会话**；不是已完成的生产飞书集成。

1. 企业飞书管理员在 `https://open.feishu.cn` 创建 **企业自建应用**，申请网页/客户端内网页身份认证能力，配置应用可用员工范围；如采用浏览器 OAuth，则另需配置重定向 URL 和 `state` 校验流程（本包当前只有客户端内 H5 code 交换端点）。
2. 获得 App ID、App Secret：仅在服务器环境变量设置 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`；禁止放到 Git、客户端 JS、截图或聊天记录。
3. 管理员通过飞书 API 或管理控制台合法获取员工 `open_id` 并明确公司身份映射；先用 `python -m platform_core.cli provision` 建立第一个 admin。后续 admin 可用受保护 API 添加员工。未加入白名单的飞书账号默认 403。
4. 手机飞书 H5 页面使用官方 `tt.requestAccess` 取得一次性授权码，向同域 `/v1/mobile/auth/feishu` POST `{"code":"一次性授权码"}`；服务端验证飞书身份、查找已开通且已绑定 open_id 的员工，并返回短期 Bearer 会话。**当前 H5 实现使用 Bearer，不是 Cookie**。不要自行改用旧的 `/platform/v1/auth/feishu/exchange`。
5. 企业应用网页 URL 应指向你最终部署的 HTTPS 前端，不应直接指向 Python 内网端口；前端和平台 API 必须通过同一个公开域名或经额外精确的 Cookie/CORS 设计。
6. 在 Android 与 iOS 飞书客户端分别做登录、退出、过期、禁用账户、员工隔离测试。真实运行时还需要限流、账号绑定审批、审计与密钥轮换。

官方入门：https://open.feishu.cn/document/client-docs/build-login-free-system-
以及 https://open.feishu.cn/document/client-docs/h5/development-guide/step-3

⚠️ 若未来要做独立 App，可进一步接 OAuth 浏览器/原生登录，在授权码与 token 之间做安全交换；不能让原生 App 伪造或直接提交 open_id。
