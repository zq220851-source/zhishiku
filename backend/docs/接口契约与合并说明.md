# MedRep Coach｜平台后端接口契约与后续合并规范

**这是一套独立新增的平台服务，没有更改你上传的 V2 三模块业务代码。**

## 1. 外部 API（均置于同一个 HTTPS 域名下）

代理规则：`https://coach.example.com/platform/v1/*` → 服务内部 `/v1/*`。

| 端点 | 功能 | 权限 |
|---|---|---|
| `GET /platform/healthz` | 存活检查 | 无，但对外健康端点需限流 |
| `POST /platform/v1/auth/feishu/exchange` | 飞书 JSAPI 临时 code 验证并设 HttpOnly 会话 Cookie | 验证过的 Feishu code，且账号预先启用 |
| `GET /platform/v1/auth/me` | 当前用户及角色（不返回 open_id） | 已登录 |
| `POST /platform/v1/auth/logout` | 注销并服务端撤销会话 | 已登录，校验请求来源 |
| `GET /platform/v1/me/state/{module}/{key}` | 读取自己跨设备个人状态 | 已登录，仅本人 |
| `PUT /platform/v1/me/state/{module}/{key}` | 写入自己状态，使用 revision 避免覆盖 | 已登录，仅本人 |
| `DELETE /platform/v1/me/state/{module}/{key}` | 删除自己状态 | 已登录，仅本人 |
| `GET /platform/v1/admin/users` | 查看本企业账号 | 仅 admin |
| `POST /platform/v1/admin/users` | 启用一个已有飞书 open_id 的账号 | 仅 admin |
| `PATCH /platform/v1/admin/users/{id}` | 修改员工角色、停用账号 | 仅 admin，无法修改自己的角色/状态 |

`GET /v1/me/state/daily/read` 返回 `{ "value": { "items": [] }, "revision": 1, "updated_at": 1790000000 }`。

`PUT /v1/me/state/daily/read` 请求示例：

```json
{
  "expected_revision": 1,
  "value": { "items": ["article-001", "article-002"] }
}
```

当 revision 已变，返回 409；前端需先拉取最新数据并执行合理合并。允许的 module：`coach`, `review`, `daily`, `ui`。每个 key 最多 64 KiB，适合“日报已读、收藏、偏好”，**不适合大体积聊天/语音/医学资料存储**。

## 2. 与已有模块对接时的边界

- **主应用 Next.js `medrep_coach_with_ai_rules/`**：每个受保护 API 先 `requirePlatformUser(request)`，再根据 user.id 检查训练会话 `owner_user_id`；现有 sessions 表还没有 owner 列，必须增量迁移，不能用客户端传来的 user_id 代替服务端身份。
- **模块一 FastAPI `module1_source/`**：停用浏览器随机 `medrep_owner` 作为唯一真实身份的方式；引入平台身份，并对原有 `runs.owner` 的迁移做安全计划。现有 localhost 保护不可直接删除。
- **模块二 Next.js `module2/`**：正式路径上彻底禁止 `switchRole` 测试接口；将 `Actor` 从测试 Cookie 切换成平台 user.id / role，但要先处理角色枚举映射和 `Store.owner` 的历史数据。
- **模块三 `medrep-daily/`**：日报收藏/已读等原 localStorage 个人状态可逐步迁移至 `/v1/me/state/daily/*`；现有 Cloudflare Worker 与审核内容流程继续独立管理。
- **飞书 `open_id`**：作为外部身份映射键，所有业务表使用平台生成的内部 UUID `user.id`；不直接用人名、手机号或 open_id 当业务主键。

## 3. 源码并行开发的合并方式

1. 本目录单独维护 `platform_core/`、`alembic/`、`compose.yaml` 和示例，不改你现在的 `medrep_coach_with_ai_rules/`、`module1_source/`、`medrep-daily/`。
2. 你后续提供 V3 业务代码和 UI 时，把平台服务和业务仓库合并，再逐个接口引入 `requirePlatformUser`；**不要直接用此包替换业务源代码**。
3. 先给所有写入用户数据的 API 增加可信身份/owner 检查，随后打通线上访问；未改造的模块继续仅本机访问。
4. 对数据库迁移必须先备份，检查表字段、SQL 约束、业务 ID、旧记录归属，不能仅根据浏览器 Cookies 推测真实员工是谁。
