# 云端测试环境操作手册（尚未执行实际云部署）

本项目 Compose 仅包含 **平台身份/偏好服务 + PostgreSQL**，**不是整个 MedRep Coach 三模块云端系统**。

## 前提

- 一台支持 Docker Engine + Compose V2 的 Linux 云主机；公网端口对外只开放 443，SSH 尽可能限定源 IP。
- 已有 HTTPS 域名，准备 Caddy/Nginx/TLS 或云负载均衡；确认所在地区的法律、域名备案和敏感业务数据政策。
- 在云服务器私有目录保存 `.env`，设置为 `chmod 600`。所有密码用随机生成值替换示例，`POSTGRES_PASSWORD` 与 `DATABASE_URL` 中保持一致。

## 首次启动（只适用测试环境）

```bash
cp .env.example .env
# 在服务器上编辑 .env，使用真实的云数据库密码和飞书凭证
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
# 仅本机可访问 127.0.0.1:18080，不能直接公网打开
curl http://127.0.0.1:18080/healthz
```

启动顺序：`db` 健康检查通过 → `migrate` Alembic 迁移完成 → `platform` 开始服务（依赖 Compose 的 `service_healthy` / `service_completed_successfully`）。

```bash
# 获取由企业授权确认的第一个管理员 Feishu open_id 后：
docker compose exec platform python -m platform_core.cli provision \
  --tenant-id company-internal --open-id 'ou_your_real_id' --name '管理员' --role admin
```

注意：**真实 API 尚不能通过浏览器访问，直到你正确配置 DNS/HTTPS 反向代理及同源前端。** `examples/Caddyfile.example` 仅说明反向代理路径的思路，不自动完成 DNS/HTTPS。

## 数据持久化与备份

- PostgreSQL 使用 Docker 命名卷 `platform_postgres`，容器重启后仍保存数据；但单个卷绝不是异地备份。
- 运行 `./scripts/backup_postgres.sh` 生成 `backup/*.dump`；把备份安全加密后保存到不同设备/区域，按公司策略定期备份并做恢复演练。
- 恢复通常需要新建空数据库，执行 `pg_restore`，并核对记录数、登录、个人状态；**不要直接覆盖生产数据库**。
- 此备份脚本不包括当前 V2 的三个 SQLite 或 Cloudflare R2 文件；业务服务接入后需另制定统一备份清单。

## 更新及回滚

1. 做可恢复的快照/备份；
2. 先看 Alembic 变更是否向前兼容；
3. 再更新 `platform` 镜像；
4. 验证健康、飞书登录和双账号隔离；
5. 若出现问题，先回滚应用镜像，**不要盲目执行数据库 downgrade**。

## 禁止事项

- 直接将 PostgreSQL 5432 端口开放公网；
- 使用 `.env.example` 中的示例密码真实上线；
- 在未接入服务端账号授权时，解除模块一/二的 localhost 安全边界；
- 把飞书 AppSecret、API Key、医生/员工信息提交到仓库或聊天中。
